## 2. Android (Google Play)

### 2-1. 릴리스 keystore 만들기 (최초 1회)

```powershell
$kt = "C:\Users\gks93\.jdks\corretto-17.0.19\bin\keytool.exe"
& $kt -genkeypair -v -keystore upload-keystore.jks -storetype JKS `
  -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```

⚠️ **이 파일과 비밀번호를 잃어버리면 같은 앱을 영원히 업데이트할 수 없다.**
저장소에 커밋하지 말고(이미 `.gitignore` 처리됨) 별도 안전한 곳에 백업할 것.

### 2-2. 로컬에서 빌드하려면

`businesscard_qr_app/android/key.properties` 를 만든다(커밋 금지):

```properties
storeFile=../upload-keystore.jks
storePassword=<keystore 비밀번호>
keyAlias=upload
keyPassword=<키 비밀번호>
```

```bash
cd businesscard_qr_app
flutter build appbundle --release --build-name=1.0.0 --build-number=1
# → build/app/outputs/bundle/release/app-release.aab
```

### 2-3. CI 로 빌드하기 (권장)

GitHub → Settings → Secrets and variables → Actions 에 등록:

| Secret | 값 |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | `base64 -w0 upload-keystore.jks` 결과 |
| `ANDROID_KEYSTORE_PASSWORD` | keystore 비밀번호 |
| `ANDROID_KEY_ALIAS` | `upload` |
| `ANDROID_KEY_PASSWORD` | 키 비밀번호 |
| `APP_ENV_FILE` | 앱 `.env` 파일 내용 전체 |

Actions 탭 → **App · Android release (AAB)** → Run workflow → 아티팩트 다운로드.

### 2-4. Play Console

1. 앱 만들기 (앱 이름 `명함QR`, 기본 언어 한국어, 앱/무료 선택)
2. **앱 콘텐츠** 를 전부 채운다 — 개인정보처리방침 URL, 광고 여부(없음), 콘텐츠 등급 설문, 타겟 고객, 데이터 보안(§6)
3. **비공개 테스트** 트랙에 AAB 업로드 → 테스터 등록 → 설치 확인
   - 인앱결제 테스트는 **트랙에 올라간 빌드**로만 된다. 로컬 debug 로는 상품 조회가 안 된다.
4. 프로덕션 트랙 제출

> `versionCode`(= `--build-number`)는 업로드할 때마다 **반드시 커져야 한다.** 같은 값이면 거부된다.

## 3. iOS (App Store)

Windows 에서는 아카이브가 불가능하므로 **GitHub Actions macOS 러너**로 빌드한다.

### 3-1. Apple 쪽 준비

1. Apple Developer Program 가입 (연 $99)
2. **Identifiers** → App ID 등록: `kr.co.businesscardqr.app`
   - Capabilities 에서 **In-App Purchase** 체크
3. **Certificates** → Apple Distribution 인증서 발급 → 키체인에서 `.p12` 로 내보내기
4. **Profiles** → App Store 배포용 프로비저닝 프로파일 생성 (위 App ID + 위 인증서)
5. **App Store Connect** → 앱 등록 (이름 · 기본 언어 · 번들 ID 연결)
6. **Users and Access → Integrations → App Store Connect API** 에서 키 발급 (`.p8`, Key ID, Issuer ID)

### 3-2. GitHub Secrets

| Secret | 값 |
|---|---|
| `IOS_CERTIFICATE_P12_BASE64` | `.p12` 를 base64 인코딩 |
| `IOS_CERTIFICATE_PASSWORD` | `.p12` 내보낼 때 건 비밀번호 |
| `IOS_PROVISIONING_PROFILE_BASE64` | `.mobileprovision` base64 |
| `IOS_TEAM_ID` | 팀 ID (10자리) |
| `APPSTORE_ISSUER_ID` / `APPSTORE_KEY_ID` / `APPSTORE_PRIVATE_KEY` | API 키 정보 |
| `APP_ENV_FILE` | 앱 `.env` 내용 전체 |

Actions → **App · iOS release (TestFlight)** → Run workflow → TestFlight 에 올라간다.

### 3-3. 심사에서 자주 걸리는 것

- **구매 복원 버튼** — 구독 앱은 필수. 이미 프로 화면에 넣어 뒀다.
- **계정 삭제** — 앱 안에서 가능해야 한다. `⋮` 메뉴에 있다.
- **로그인 없이 볼 수 있는 게 없는 앱**은 심사자용 테스트 계정을 요구한다.
  카카오 로그인이라 심사자가 직접 가입할 수 없으므로, **App Review Information 에 테스트 계정을 반드시 적을 것.**

## 7. 카카오 — 사용자 담당 ⛔

> 사용자가 직접 하기로 한 부분. **안 하면 로그인이 안 되므로 출시 전 반드시 필요하다.**

1. **릴리스 키 해시 등록 (Android)** — 키 해시는 서명 keystore 마다 다르다.
   릴리스 keystore 로 뽑아 카카오 개발자센터(앱 ID `1315157`) → 플랫폼 Android 에 **추가**한다.
   패키지명도 `com.example.businesscard_qr` → **`kr.co.businesscardqr.app`** 로 바꿔야 한다.

   ```powershell
   $ks="upload-keystore.jks"; $kt="C:\Users\gks93\.jdks\corretto-17.0.19\bin\keytool.exe"
   $sha1=(( & $kt -list -v -alias upload -keystore $ks | Select-String 'SHA1:') -replace '.*SHA1:\s*','') -replace '[^0-9A-Fa-f]',''
   $b=for($i=0;$i -lt $sha1.Length;$i+=2){[Convert]::ToByte($sha1.Substring($i,2),16)}; [Convert]::ToBase64String([byte[]]$b)
   ```

   > Play 앱 서명(Play App Signing)을 쓰면 Google 이 재서명하므로,
   > **Play Console 이 알려주는 최종 SHA-1 로도 키 해시를 한 번 더 등록**해야 한다.

2. **iOS 플랫폼 등록** — 카카오 개발자센터에 번들 ID `kr.co.businesscardqr.app` 추가.

3. **iOS AppDelegate 콜백 처리** — `ios/Runner/AppDelegate.swift` 에 카카오 URL 처리가 **아직 없다.**
   `Info.plist` 의 URL 스킴·`LSApplicationQueriesSchemes` 는 이미 넣어 뒀으므로 AppDelegate 만 채우면 된다.
   (이게 없으면 카카오톡으로 갔다가 앱으로 돌아오지 못한다.)

## 9. 아직 안 한 것 (출시 후 과제)

- **RTDN / App Store Server Notifications** — 환불·취소를 스토어가 먼저 알려주는 웹훅.
  지금은 만료 시각 기반이라, 환불 즉시 회수가 필요해지면 붙인다. ([`인앱결제_설계.md`](인앱결제_설계.md) §5)
- **R8 난독화** — 카카오 SDK 리플렉션 경로가 기기에서만 깨질 수 있어 꺼 두었다.
  켜려면 `proguard-rules.pro` 를 채우고 실기기로 검증할 것.
- **개인정보처리방침 다국어** — 지금은 한국어·영어 2종. 일·중·스페인·독일어는 필요해지면 추가한다.

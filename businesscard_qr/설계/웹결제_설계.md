# 웹 결제 설계 — 프로 평생 이용권 (토스페이먼츠)

> 2026-11-26. 웹앱 전환(`웹앱_전환_설계.md` §5)의 결제 부분. 이 문서가 백엔드·웹·QA 의 공통 기준이다.

## 0. 결론 먼저

- **상품은 하나: 프로 평생 이용권.** 한 번 결제하면 영구히 프로(명함 무제한). 구독·기간권 없음.
- **결제대행: 토스페이먼츠 "결제창"(SDK v2, API 개별 연동 키).** 카드·간편결제.
- **가격은 서버가 정한다** — `APP_BILLING_LIFETIME_PRICE`(기본 9,900원). 주문을 만들 때 주문에 고정된다.
- **돈은 서버의 "승인" 요청에서만 빠진다.** 그래서 모든 검사는 승인 직전에 한다.
  승인하지 않은 결제는 토스가 10분 뒤 자동 취소한다 → "의심스러우면 승인하지 않는다"가 언제나 안전하다.
- **환불은 운영자가 토스 관리자 화면에서 한다** → 웹훅 → 서버가 토스에 다시 물어 확인 → 이용권 회수.

## 1. 상품

| | 값 |
|---|---|
| 상품 ID | `pro_lifetime` (코드 상수 `LifetimePass.PRODUCT_ID` — DB 에 남는 식별자라 고정) |
| 주문명 | `명함QR 프로 평생 이용권` (토스 결제창·영수증·카드 명세서에 찍힌다) |

"평생"의 뜻은 약관 제6조: *계정이 유지되고 서비스가 운영되는 동안 추가 결제 없이*.

## 2. 데이터 — `web_orders`

스토어 구독(`subscriptions`)과 **따로** 둔다. 구독은 "만료일이 있는 영수증", 이건 "주문 → 승인 → (환불)" 이라 모양이 다르다.

| 컬럼 | 설명 |
|---|---|
| `id` | Long PK (코드컨벤션 §4-1) |
| `order_id` | 토스에 넘기는 주문번호. `bq_` + UUID 32자. **UNIQUE** |
| `user_id` | 세션 주체에서만 채운다 |
| `product_id` | `pro_lifetime` |
| `amount` | 주문 시점 가격(원). 승인 요청 금액과 비교하는 기준 |
| `status` | `PENDING` → `PAID` → (`CANCELED`) |
| `payment_key` | 토스 결제 키. 승인 후 채움. **UNIQUE** — 결제 한 건이 두 주문에 붙지 못한다 |
| `method` | "카드" 등(문의 응대용). 카드번호 같은 건 받지도 저장하지도 않는다 |
| `approved_at`, `canceled_at`, `created_at`, `updated_at` | |

- 테이블은 `ddl-auto: update` 로 운영 MySQL 에 자동 생성된다.
- **회원 탈퇴해도 지우지 않는다** — 전자상거래법상 대금결제 기록 5년 보관(구독과 같다).
  같은 카카오 계정으로 다시 가입하면 `user_id` 가 같아 이용권이 다시 적용된다(약관 제9조에 명시).

## 3. API 계약

| 메서드 | 경로 | 인증 | 설명 |
|---|---|---|---|
| GET | `/api/billing/web/lifetime` | **공개** | 가격·판매 여부. 첫 화면 요금 안내에도 쓴다 |
| POST | `/api/billing/web/orders` | 로그인 | 주문 생성(본문 없음) |
| POST | `/api/billing/web/orders/{orderId}/confirm` | 로그인 | 승인 |
| POST | `/api/billing/web/webhook` | **공개**(토스가 부름) | 결제 상태 변경 알림 |

```jsonc
// GET /api/billing/web/lifetime
{ "product_id": "pro_lifetime", "amount": 9900, "currency": "KRW",
  "available": true,            // false = 키 없음 → 화면은 "결제는 곧 열려요"
  "free_card_limit": 3 }

// POST /api/billing/web/orders → 웹앱이 이 값으로 결제창을 연다
{ "order_id": "bq_…", "product_id": "pro_lifetime", "amount": 9900, "currency": "KRW",
  "order_name": "명함QR 프로 평생 이용권", "client_key": "test_ck_…" }   // 공개 키. 시크릿 키는 절대 안 나간다

// POST …/confirm  요청 — 토스 성공 주소의 값을 그대로 옮긴다
{ "payment_key": "…", "amount": 9900 }
// 응답 = 바뀐 자격(GET /api/billing/entitlement 와 같은 모양)
{ "pro": true, "lifetime": true, "product_id": "pro_lifetime", "card_count": 4 }   // card_limit·expires_at 없음 = 무제한·영구
```

`GET /api/billing/entitlement` 에 `lifetime` 필드(boolean)가 추가됐다. 평생 이용권이면 구독보다 먼저 보여준다.

### 오류 코드 (`PaymentException`)

| errorCode | HTTP | 언제 | 화면 |
|---|---|---|---|
| `PAYMENT_UNAVAILABLE` | 503 | 키 없음 / 토스 응답 없음·5xx·타임아웃 / 토스 인증 실패(키 오류) | "잠시 후 다시" + 재시도 버튼 |
| `PAYMENT_REJECTED` | 400 | 카드사·토스 거절. **토스의 안내 문장을 그대로** 싣는다 | 한국어는 토스 문장, 다른 언어는 일반 문구 |
| `PAYMENT_AMOUNT_MISMATCH` | 400 | 요청 금액 ≠ 주문 금액(변조) | 처음부터 다시 |
| `ALREADY_LIFETIME` | 409 | 이미 평생 이용권이 있다 | |
| `ORDER_CLOSED` | 409 | 다른 결제로 끝났거나 환불된 주문 | |
| (404) | 404 | 없는 주문 **또는 남의 주문** — 존재 여부도 알리지 않는다 | |

## 4. 흐름과 안전장치

```
프로 화면 ─POST /orders→ 서버: PENDING 주문(금액 고정)
   │
   └─ 토스 SDK(js.tosspayments.com/v2/standard) → requestPayment(method CARD)
        PC: 결제창 iframe / 모바일: 토스 결제 페이지로 이동
           │
           ├─ 성공 → /pro/success?paymentKey&orderId&amount ─POST /confirm→ 서버 ─→ 토스 승인 API
           └─ 실패·취소 → /pro/fail?code&message   (승인 전이라 돈이 빠지지 않았다)
```

**승인(`WebCheckoutService.confirm`) — 토스를 부르기 전에 전부 막는다**

1. 주문이 **내 것**인가 (아니면 404)
2. 이미 **같은 결제 키로 PAID** 면 토스에 다시 묻지 않고 성공(새로고침·뒤로가기 — 멱등)
3. `PENDING` 인가 (아니면 `ORDER_CLOSED`)
4. 요청 금액 == 주문 금액 (아니면 `PAYMENT_AMOUNT_MISMATCH`, 토스 호출 없음)
5. **다른 주문으로 이미 평생 이용권이 있는가** — 탭 두 개에서 둘 다 결제한 경우. 두 번째는 승인하지 않는다 →
   토스가 자동 취소 → 돈이 두 번 빠지지 않는다
6. ── 토스 승인(트랜잭션 밖, `Idempotency-Key: paymentKey`) ──
7. 응답이 `DONE` 이고 **주문번호·금액이 우리 주문과 같은가** (다른 주문의 결제를 끌어다 쓰는 것 차단)
8. `WebOrderRecorder.markPaid` (짧은 트랜잭션, 쓰기 직전 재확인)

**놓친 승인의 복구**

| 상황 | 복구 |
|---|---|
| 토스는 승인했는데 응답을 못 받음(타임아웃·재시작) → 사용자가 다시 시도 | 토스가 `ALREADY_PROCESSED_PAYMENT` → **결제 조회로 확인 후 PAID** |
| 승인 직후 사용자가 창을 닫아 성공 화면이 못 알림 | 웹훅(DONE) → 조회 확인 → PAID |
| 같은 승인이 동시에 두 번(이중 클릭) | 토스 `ALREADY_PROCESSING_REQUEST` → 503 "잠시 후" → 재시도는 2번 경로로 성공 |

**웹훅(`handleWebhook`) — 본문을 믿지 않는다**

- 웹훅 주소는 누구나 부를 수 있다. 본문은 "바뀐 게 있다"는 신호로만 쓰고 **실제 상태는 토스 결제 조회 API 로** 확인한다.
- 모르는 주문 → 토스에 묻지도 않고 200(아무나 토스 API 를 두들기게 두지 않는다).
- PAID 주문은 **우리가 저장한 결제 키**로 조회한다(본문의 키를 쓰지 않는다).
- 전액 취소(`CANCELED`) → 이용권 회수. 부분 취소(`PARTIAL_CANCELED`)는 그대로 둔다(평생 이용권은 나눌 수 없는 상품).
- 토스에 물어볼 수 없으면 **503** → 토스가 나중에 다시 보낸다(최대 7회). 확인 못 한 채 200 을 주면 환불 소식이 사라진다.

**타임아웃**: 토스 전용 `tossRestClient` — 연결 5초, 응답 25초(승인은 카드사까지 다녀와서 느릴 수 있다).
웹앱 요청 타임아웃 35초보다 짧게 잡아 화면이 먼저 끊기지 않게 했다.

## 5. 웹 화면

| 경로 | 화면 |
|---|---|
| `/` | 첫 화면 하단에 **요금 안내**(무료 N장 / 평생 이용권 가격 — 결제가 열려 있을 때만) + 사업자 정보 |
| `/pro` | 가격 · 구매 버튼 · **환불 규정 고지(결제 전)** · 사업자 정보. 키가 없으면 "결제는 곧 열려요" |
| `/pro/success` | 승인 요청 → 완료 / 실패(재시도 가능한 오류면 재시도 버튼) / 잘못된 주소 |
| `/pro/fail` | 사유(코드로 고른다 — 토스의 한국어 message 를 화면에 비추지 않는다) + "돈은 빠지지 않았어요" |

- SDK 는 **구매 버튼을 누를 때만** 싣는다(`lib/payment.js` `loadTossSdk`). 프로 화면 밖에서는 외부 스크립트를 받지 않는다.
- 비회원 결제(`customerKey: TossPayments.ANONYMOUS`) — 토스에 우리 회원 식별자를 넘기지 않는다.
- 승인 요청은 결제 키당 한 번만 보낸다(`confirmOnce`) — StrictMode 이중 실행에서도 성공을 실패로 보여주지 않게.
- **CSP**(`SecurityConfig`): `script-src` 에 `https://js.tosspayments.com` 하나, `frame-src`·`connect-src`·`img-src`·`form-action` 에 `https://*.tosspayments.com`.
  인라인 스크립트는 여전히 막혀 있다.
- 문구는 6개 언어. 결제창 자체는 한국어(결제창 언어 옵션은 검증 전이라 넣지 않았다 — §9).

**환불 규정(기본값 — 확인 필요)**: 결제 후 7일 이내 + 무료 한도를 넘겨 명함을 만들기 전이면 전액.
프로 기능을 쓴 뒤에는 디지털콘텐츠 제공 개시로 철회 제한 가능(무료 플랜이 "미리 써 보기" 역할).
서비스 종료 시 구매 후 1년 이내면 전액 환불(약관 제8조).

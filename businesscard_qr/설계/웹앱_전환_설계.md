## 3. 인증: HttpOnly 쿠키

### 3-1. 왜 쿠키인가
코드컨벤션 §7 — **토큰을 localStorage 에 저장하지 않는다.** localStorage 는 XSS 한 번에
토큰이 그대로 유출되고, 스크립트가 읽을 수 있는 곳에 장기 자격증명을 두는 건 피한다.

### 3-2. 계약 변경

`POST /api/auth/kakao` — 응답 본문은 그대로 두고 **Set-Cookie 를 추가**한다.

```
Set-Cookie: bq_access=<JWT>;  HttpOnly; Secure; SameSite=Strict; Path=/;   Max-Age=3600
Set-Cookie: bq_refresh=<JWT>; HttpOnly; Secure; SameSite=Strict; Path=/api/auth; Max-Age=1209600
```

- `HttpOnly` — JS 가 못 읽는다(XSS 로도 탈취 불가)
- `SameSite=Strict` — **CSRF 방어의 본체**. 웹 프론트가 API 와 **같은 오리진**에서 서빙되므로
  Strict 로 조여도 정상 동작하고, 남의 사이트에서 날린 요청에는 쿠키가 붙지 않는다.
- `Secure` — 운영만(`app.cookie.secure`). 로컬 http 개발을 막지 않기 위해 설정값으로 둔다.
- refresh 쿠키의 `Path` 를 `/api/auth` 로 좁혀, 일반 API 요청에 장기 토큰이 따라다니지 않게 한다.

신규:
- `POST /api/auth/refresh` — 본문 없이 **쿠키만으로도** 갱신되게 한다(기존 본문 방식도 유지).
- `POST /api/auth/logout` — 두 쿠키를 즉시 만료시킨다. (신규)

### 3-3. 필터

`JwtAuthenticationFilter` 는 토큰을 **Authorization 헤더 → 없으면 `bq_access` 쿠키** 순으로 찾는다.

> **헤더 경로를 걷어내지 않는 이유:** 이미 동작하는 코드라 두면 비용이 0 이고,
> 지우는 쪽이 오히려 작업이다. 앱을 되살릴 길을 공짜로 남겨 둔다.
> 쿠키를 받아들이는 데 드는 실제 비용은 "단순함"이 아니라 **CSRF 방어**이고, 그건 §3-2 로 처리했다.

### 3-4. 카카오 로그인 (웹)

앱은 네이티브 SDK, 웹은 **JavaScript SDK** 를 쓰지만 **백엔드 계약은 같다** —
둘 다 카카오 액세스 토큰을 받아 `POST /api/auth/kakao` 로 보낸다.
같은 카카오 앱(ID `1315157`)이라 `APP_KAKAO_EXPECTED_APP_ID` 검증도 그대로 통과한다.

⛔ **사용자 작업**: 카카오 개발자센터에 **Web 플랫폼 + 사이트 도메인 + Redirect URI** 등록,
그리고 **JavaScript 키** 발급. (네이티브 앱 키와 다른 값이다.)

## 4. 공개 명함 보기 — `/c/:id`

### 4-1. 무엇이 달라지나
앱의 QR 은 **5분 만료 vCard 다운로드 링크**를 담는다. 눈앞에서 바로 스캔하는 용도라 그건 맞지만,
웹에서는 **카톡·메일·메신저로 링크를 보내는 것**이 자연스러운 공유 방식이다. 링크가 5분 뒤 죽으면 쓸 수 없다.

그래서 **영구 공개 페이지**를 둔다. QR 도 이 페이지를 가리키게 한다.

### 4-2. 신규 API

`GET /api/business-cards/{cardId}/public` — **인증 불필요**

```json
{
  "success": true,
  "data": {
    "id": "…",
    "full_name": "홍길동",
    "phone": "010-…", "email": "…", "website": "…",
    "organization": "…", "title": "…", "address": "…", "note": "…",
    "business_card_image_url": "https://…/uploads/…",
    "vcf_download_url": "…/api/business-cards/{id}/public/vcf"
  }
}
```

`GET /api/business-cards/{cardId}/public/vcf` — **인증·토큰 불필요**. vCard 파일을 바로 내려준다.

### 4-3. 이 노출을 받아들이는 근거
- **명함은 원래 남에게 주는 물건이다.** 공유가 안 되면 제품이 성립하지 않는다.
- `cardId` 는 UUID 라 열거·추측이 불가능하다(`resolveCardId` 가 UUID 형식을 강제하는 이유이기도 하다).
  즉 **링크를 아는 사람만** 볼 수 있다 — 종이 명함을 받은 사람만 볼 수 있는 것과 같다.
- 명함 **이미지**는 `/uploads/**` 로 이미 공개였고, 조회수 증가도 이미 공개 엔드포인트다.
  새로 생기는 노출은 "텍스트 필드"뿐이고, 그건 QR 로 뿌리던 vCard 에 이미 다 들어 있었다.
- 응답은 **축소형**이다 — 다운로드 토큰·소유자 id·내부 타임스탬프는 내보내지 않는다.

> ⚠️ 그래도 이건 **정책 변경**이다. "링크를 아는 사람은 누구나 볼 수 있다"가 싫다면
> 카드별 `is_public` 플래그로 바꿔야 한다(컬럼 1개 + 토글 UI). 지금은 넣지 않았다.

## 5. 결제: 국내 PG

스토어를 안 거치므로 **Play/Apple 정책도, 30% 수수료도 적용되지 않는다**(PG 수수료 ~3%).
기존 `subscriptions` 표와 `EntitlementService` 는 **그대로 재사용**한다 —
`store` enum 에 값을 하나 더하고, 검증기를 하나 더 끼우면 된다
(`StoreReceiptClient` 를 인터페이스로 둔 설계가 여기서 값을 한다).

### 5-1. 결정됨 (2026-11-26) — 평생 이용권, 토스페이먼츠

사용자 결정: **"기간권보다 한 번 구매하면 영구"**. 구독·기간권 대신 **프로 평생 이용권** 하나만 판다.
결제대행은 **토스페이먼츠 결제창(SDK v2)** 직접 연동.
`subscriptions` 표는 재사용하지 않았다 — "만료일 있는 영수증"과 "주문→승인→환불"은 모양이 달라 `web_orders` 를 따로 뒀다.

→ 설계·API 계약·배포 체크리스트는 **`웹결제_설계.md`** 가 기준이다.

## 6. PWA

- `manifest.webmanifest` — 이름(언어별), 아이콘, `display: standalone`, 테마색(Halo `--point`)
- 서비스워커 — **앱 셸만 캐시**한다. 명함 데이터는 캐시하지 않는다
  (다른 기기에서 수정했는데 낡은 걸 보여주면 안 된다 — 앱의 캐시 전략 메모와 같은 판단)
- iOS 제약: 설치가 Safari 공유 메뉴 수동이고 푸시는 홈화면 추가 후에만 된다.
  이 제품은 푸시를 쓰지 않으므로 영향 없다.

## 8. 배포 체크리스트 ⭐

### 8-1. 카카오 개발자센터 (사용자 작업)

앱 ID `1315157` → 다음을 **추가**한다(앱용 설정은 지우지 않는다).

| 위치 | 넣을 값 |
|---|---|
| 앱 설정 > 플랫폼 > **Web** > 사이트 도메인 | `https://businesscardqr-production.up.railway.app` |
| 카카오 로그인 > **활성화** | ON |
| 카카오 로그인 > **Redirect URI** | `https://businesscardqr-production.up.railway.app/api/auth/kakao/callback` |
| 카카오 로그인 > 보안 > **Client Secret** | 발급 + **사용함** (권장) |
| 앱 키 > **REST API 키** | 아래 env 로 |

> ⚠️ Redirect URI 는 **글자 하나까지** 같아야 한다(끝의 `/` 하나도). 서버는 `APP_PUBLIC_BASE_URL + /api/auth/kakao/callback` 으로 만든다.
> 로컬에서도 시험하려면 `http://localhost:8081/api/auth/kakao/callback` 도 추가로 등록한다.

### 8-2. Railway env (businesscard_qr 서비스)

| env | 값 | 비고 |
|---|---|---|
| `APP_KAKAO_REST_API_KEY` | 카카오 REST API 키 | **없으면 웹 로그인이 안 된다** (로그인 화면으로 되돌아옴) |
| `APP_KAKAO_CLIENT_SECRET` | 카카오 Client Secret | Client Secret 을 켰을 때 |
| `APP_COOKIE_SECURE` | `true` | **운영 필수.** 빠지면 세션 쿠키가 평문 http 로도 실린다 |
| `APP_PUBLIC_BASE_URL` | `https://businesscardqr-production.up.railway.app` | 이미 있음. Redirect URI·공유 링크의 기준 |
| `APP_KAKAO_EXPECTED_APP_ID` | `1315157` | 이미 있음 |
| `APP_BILLING_TOSS_CLIENT_KEY` / `APP_BILLING_TOSS_SECRET_KEY` / `APP_BILLING_LIFETIME_PRICE` | 토스 키·가격 | 결제용 — `웹결제_설계.md` §7. 없으면 결제만 꺼진 채 정상 동작 |

### 8-3. 프론트를 고쳤으면 — static 까지 커밋

Railway 이미지(Dockerfile)는 **JDK 이미지라 node 가 없다.** 그래서 Docker 빌드는 프론트를 빌드하지 못하고
**커밋된 `src/main/resources/static/`** 을 그대로 쓴다. 프론트를 고친 뒤에는:

```bash
# node 가 PATH 에 있으면 gradle 이 알아서 frontend → static 까지 채운다
./gradlew :businesscard_qr:test
git add businesscard_qr/frontend businesscard_qr/src/main/resources/static
```

`static/` 을 빼고 커밋하면 **운영에는 옛 화면이 그대로 나간다** — 가장 흔한 실수다.

### 8-4. 배포 후 확인

- [ ] `/` 로그인 화면이 뜨고 카카오 버튼 → 동의 → `/cards` 로 돌아온다
- [ ] 명함 등록(사진 포함) → 상세 → **공유 링크를 시크릿 창에서 열면** 로그인 없이 명함이 보인다
- [ ] 공개 명함에서 "연락처에 저장" → 폰 연락처에 들어간다
- [ ] 크롬 주소창의 설치 아이콘(또는 iOS 공유 > 홈 화면에 추가)으로 설치되고, 이름이 언어대로 뜬다
- [ ] 개발자도구 Console 에 CSP 위반이 없다

## 9. 구현 메모 — 나중에 헷갈리지 않게

- **state 쿠키만 `SameSite=Lax`, 세션 쿠키는 `Strict`.** 카카오 → 콜백은 교차 사이트 이동이라
  state 쿠키가 Strict 면 로그인이 100% 깨진다. `KakaoWebLoginApiIntegrationTest.authorize_stateCookieIsLax_notStrict` 가 지킨다.
- **CSP 는 인라인 스크립트를 막는다.** 정적 문서의 스크립트도 `/legal.js` 로 뺐다. 새 정적 문서를 만들면 `<script>` 를 인라인으로 넣지 말 것.
- **SPA 경로는 서버(`SpaController`)와 프론트(`App.jsx`) 두 곳에 있다.** 화면을 추가하면 둘 다 고친다.
- **목록은 메모리 캐시**(`CardsContext`) — 앱과 같은 전략. 세션당 목록 API 1회.
- **공개 명함 링크에 들어가는 값은 반드시 `contactLinks.js` 를 거친다** — 웹사이트 칸의 `javascript:` 차단.
- doll_gacha 는 OAuth state 를 서버 메모리에 둔다(`InMemoryAuthorizationRequestRepository`) — App Sleeping 으로
  로그인 도중 재시작되면 state 가 날아간다. businesscard_qr 은 쿠키에 둬서 그 문제가 없다. (doll_gacha 는 건드리지 않았다)
- **개인정보처리방침을 웹에 맞게 고쳤다** — §8 에 "링크를 가진 사람은 명함을 볼 수 있다"는 공개 범위를 명시하고
  (이전 문구 "인증된 요청에만 이미지를 전달"은 사실과 달랐다), §9 쿠키 항목(개인정보보호법 시행령 §31 법정 기재사항)을 추가했다.
  쿠키를 새로 만들면 §9 표에 같이 적는다.

| 끝 `/`·없는 화면 주소의 404 | `/c/{id}/`, `/foo` 를 브라우저로 열면 JSON 404 원문이 보인다(QA 2026-11-26 결함 2, 낮음). 앱이 만드는 링크엔 `/` 가 안 붙는다 | 정책 결정 필요: HTML 요청(Accept: text/html)인 미지 경로만 웹앱 셸 + 404 로 줄지. API 404 는 JSON 그대로여야 한다(§9 "SPA 경로를 일일이 적는 이유") |
| 화면 컴포넌트 테스트 | 웹 테스트는 `lib/` 순수 로직만 본다(node 환경). "한도를 채우는 저장 → 상세 이동"(QA 결함 1) 같은 화면 흐름은 못 잡는다 | jsdom + Testing Library 도입 — 새 라이브러리라 senior-dev 결정 사항 |

## 11. 카톡 링크 미리보기 — "누구의 명함인지" (2026-11-26)

메신저의 미리보기 수집기는 **자바스크립트를 실행하지 않는다.** React 가 그리는 화면은 못 보고 서버가 준 HTML 의 og 태그만 읽는다.
그래서 `/c/{id}` 만은 `SpaController` 가 아니라 **`PublicCardPageController`** 가 맡아, index.html 에 태그를 끼워 내준다
(`PublicCardPageRenderer`). 사람이 열면 같은 index.html 이라 웹앱이 그대로 뜬다.

| 태그 | 값 |
|---|---|
| `<title>` | 이름 · 직함 · 회사 |
| `og:title` | 이름 |
| `og:description` | 직함 · 회사 (둘 다 없으면 언어별 안내 문구) |
| `og:image` | 명함 사진(절대 URL) / 없으면 `/icons/og-default.jpg`(1200×630, 30KB — 원본 `frontend/scripts/og-default.svg`) |
| `og:site_name` | Accept-Language 로 — 한국어 "명함QR", 그 밖 "Businesscard QR". **언어를 안 밝히면 한국어**(수집기 대부분이 안 밝힌다) |
| `og:url` | `{APP_PUBLIC_BASE_URL}/c/{id}` |

- **보안 경계는 HTML 이스케이프** — 이름·직함은 사용자 입력이다. `HtmlUtils.htmlEscape(v, "UTF-8")`(`<>&"'` 만 바꾼다. 인코딩을 안 주면 `·` 까지 `&middot;` 로 바뀐다).
  정규식 치환(`replaceFirst`)에 사용자 값을 넣지 않는다 — `$1`·`\` 가 치환 문법으로 해석된다.
- **미리보기에는 연락처(전화·이메일·주소)를 싣지 않는다** — 메신저 회사 서버가 긁어 가 대화방에 남기 때문. `PublicCardPreview` DTO 가 그 경계다.
- **검색엔진 차단**: `X-Robots-Tag: noindex, nofollow` + `<meta name="robots">`. `/uploads/**`(명함 사진)도 같은 헤더.
  robots.txt 로 `/c/` 를 막지 **않는다** — 막으면 검색엔진이 noindex 를 못 봐서 오히려 "제목 없는 결과"로 색인될 수 있다.
- **`Cache-Control: no-cache`** — 명함을 고치면 다음 공유부터 반영. 단, **카카오는 미리보기를 자체 캐시한다** —
  이미 보낸 링크의 미리보기를 바로 바꾸려면 [카카오 개발자 > 도구 > 공유 디버거]에서 캐시를 지운다.
- 없거나 지운 명함 → **404 + 태그 없는 셸**(웹앱이 "찾을 수 없어요"를 그린다).
- 서비스워커는 `/c/` 응답을 셸로 저장하지 않는다(제목이 남의 이름이라 — `sw.js` `bq-v2`).
- 개인정보처리방침 §8 에 "미리보기에 이름·직함·회사·명함 이미지가 보이고, 메신저가 보관해 삭제 뒤에도 한동안 남을 수 있다"를 적었다.

덤: 번들(`/assets/*`)에 1년 캐시(`immutable`)를 걸었다(`WebConfig`). 없으면 시큐리티 기본값(no-store)이 붙어,
서비스워커가 없는 카톡 인앱 브라우저에서 링크를 열 때마다 번들 전체를 다시 받았다.

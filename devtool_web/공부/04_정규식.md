# 04. 정규식 — 백트래킹 · ReDoS · 룩어라운드

> `/regex` 를 만들면서 정리한 것. 이 도구는 **브라우저를 167초 얼려 먹은 적이 있다.**
> 정규식이 왜 느려질 수 있는지는 문법이 아니라 **엔진이 어떻게 도는지**를 알아야 설명된다.
> 이 문서의 시간 측정은 실제로 돌린 값이다(Node 24, 이 PC 기준).

---

## 0. 한 장 요약

| | |
|---|---|
| 대부분의 엔진은 **백트래킹 NFA** | 안 맞으면 되돌아가 다른 경우를 시도한다. 그래서 **지수 시간**이 가능하다 |
| 위험한 모양 | **중첩된 수량자** — `(a+)+`, `(a*)*`, `(a|a)*` |
| 사용자 입력을 패턴으로 받으면 | 그건 **원격 코드가 아니라 원격 정지**다. 방어가 필요하다 |
| JS 에서 유일한 확실한 방어 | **Worker + `terminate()`** — 실행 중인 정규식은 다른 방법으로 못 끊는다 |

---

## 1. 엔진은 두 종류다

| | 백트래킹 NFA | DFA |
|---|---|---|
| 쓰는 곳 | **Java, JS, Python, PHP, .NET, PCRE** | RE2(Go 기본), `grep`, `awk` |
| 역참조 `\1`, 룩어라운드 | 된다 | **안 된다** |
| 최악 시간 | **입력 길이에 지수적** | 입력 길이에 **선형** 보장 |

우리가 매일 쓰는 건 대부분 백트래킹 엔진이다. 표현력을 얻는 대신 **최악 성능 보장을 포기**했다.

### 백트래킹이 도는 방식

`^(a+)+$` 로 `aaaa!` 를 검사한다고 하자.

1. 안쪽 `a+` 가 탐욕적으로 `aaaa` 를 다 먹는다
2. 바깥 `+` 가 한 번 더 반복하려는데 남은 게 `!` 라 실패
3. `$` 도 실패
4. **되돌아간다.** 안쪽 `a+` 가 `aaa` 만 먹고, 바깥이 나머지 `a` 를 먹는 조합을 시도
5. 또 실패 → 또 되돌아감 → `aa`+`aa`, `aa`+`a`+`a`, `a`+`aaa`, …

`a` 를 n개로 쪼개는 방법의 수만큼 시도한다. **2ⁿ** 이다.

```
"aaaa...a!" 를 /^(a+)+$/ 로 검사할 때
24자 →   800ms
26자 →   389ms
28자 →  1875ms
30자 → 13328ms   ← 6자 늘었는데 16배
```

**35자쯤이면 몇 분, 40자면 몇 시간이다.** 실제로 `/regex` 도구에서 이걸 만나
탭이 167초 동안 얼어붙었다. 입력이 겨우 40자였다.

## 2. ReDoS — 어떤 모양이 위험한가

**중첩된 수량자**가 핵심이다. "여러 방식으로 같은 문자열을 나눌 수 있는" 구조.

```
❌ (a+)+        수량자 안의 수량자
❌ (a*)*
❌ (a|a)*       대안이 겹친다
❌ (\w+\s?)+    공백이 선택적이라 나누는 방법이 여러 가지
❌ ^(\w+@\w+\.)+[a-z]{2,}$    흔한 "이메일 검증" 정규식이 이 모양인 경우가 많다
```

**겹치지 않게** 만들면 백트래킹할 게 없어진다.

```
✅ a+           그냥 하나로
✅ (a|b)*       대안이 서로 배타적
✅ [^@]+@[^@]+  부정 문자 클래스는 겹치지 않는다
```

### 실무에서 이게 왜 보안 문제인가

서버가 사용자 입력에 정규식을 돌린다면, 공격자는 **CPU 를 한 요청으로 100% 태울 수 있다**.
Node 처럼 단일 스레드면 그 워커가 통째로 멈춘다.
실제로 Cloudflare 가 2019년에 이걸로 30분 전역 장애를 냈다 (`.*.*=.*` 형태).

## 3. 방어하는 법

### 3.1 패턴을 사용자가 준다면 (= `/regex` 같은 도구)

**타임아웃 말고는 답이 없다.** 그리고 JS 에서 실행 중인 정규식은
`setTimeout` 으로 못 끊는다 — 같은 스레드를 정규식이 붙잡고 있으니 타이머가 돌 기회가 없다.

```js
// 유일하게 확실한 방법: 다른 스레드에서 돌리고 죽인다
const worker = new Worker("regexWorker.js");
const timer = setTimeout(() => worker.terminate(), 1000);   // 강제 종료
worker.onmessage = (e) => { clearTimeout(timer); /* 결과 */ };
```

이 프로젝트의 `lib/regexRunner.js` + `workers/regexWorker.js` 가 정확히 이것이다.
`terminate()` 는 **실행 중이어도 죽인다.** 그게 핵심이다.

### 3.2 패턴을 내가 쓴다면 (= 일반적인 서버 코드)

| 방법 | 어떻게 |
|---|---|
| **입력 길이를 먼저 자른다** | 지수 시간이라도 n이 작으면 안전하다. 검증 전에 `if (s.length > 200) reject` |
| **원자적 그룹 / 소유 수량자** | 되돌아가지 않겠다고 선언. **Java·PCRE 는 되고 JS 는 안 된다** |
| **패턴을 단순하게** | 중첩 수량자를 안 쓰면 대부분 해결된다 |
| **RE2 로 바꾼다** | 선형 시간 보장. Go 기본, Java/Node 용 바인딩도 있다 |

```java
// Java: 소유 수량자 (++, *+) — 먹은 걸 절대 안 뱉는다
Pattern.compile("^(a++)+$");     // 백트래킹이 없어 즉시 실패

// Java: 원자적 그룹
Pattern.compile("^(?>a+)+$");
```

JS 에는 둘 다 없지만 **룩어헤드로 흉내낼 수 있다.**

```js
/^(?=(a+))\1+$/.test("a".repeat(30) + "!")
// 0.24ms   ← 같은 입력에 (a+)+ 는 13328ms 였다
```

`(?=(a+))` 로 최대한 먹은 결과를 캡처해 두고 `\1` 로 그것만 쓴다.
되돌아갈 여지를 없애는 것이다.

> Java 의 `Pattern` 은 **컴파일 비용이 크다.** 메서드 안에서 `Pattern.compile()` 이나
> `String.matches()` 를 호출하면 매번 컴파일한다. `static final Pattern` 으로 한 번만 만든다.
> (`Pattern` 은 불변이고 스레드 안전하다. `Matcher` 는 아니다.)

## 4. 탐욕 · 게으름 · 소유

```js
"<a><b>".match(/<.+>/)[0]     // "<a><b>"   탐욕: 최대한 먹고 필요한 만큼 뱉는다
"<a><b>".match(/<.+?>/)[0]    // "<a>"      게으름: 최소한 먹고 필요하면 늘린다
```

| 표기 | 이름 | 동작 |
|---|---|---|
| `*` `+` `?` `{n,m}` | 탐욕 | 최대한 먹고 **되돌아가며** 뱉는다 |
| `*?` `+?` `??` | 게으름 | 최소한 먹고 **한 칸씩 늘린다** |
| `*+` `++` `?+` | 소유 (Java/PCRE) | 최대한 먹고 **절대 안 뱉는다** |

게으름이 항상 빠른 건 아니다. 매치가 뒤쪽에 있으면 게으름이 더 많이 되돌아간다.
**빠르게 만드는 건 게으름이 아니라 "되돌아갈 여지를 없애는 것"** 이다.

HTML 태그를 지울 때 `<.+>` 대신 `<[^>]+>` 를 쓰는 게 정석인 이유도 같다 —
`[^>]` 는 `>` 를 못 먹으니 되돌아갈 일이 없다.

## 5. 룩어라운드 — 위치만 보고 소비하지 않는다

```js
"가격100원".match(/(?<=가격)\d+/)[0]    // "100"  — "가격"은 결과에 안 들어간다
```

| 표기 | 이름 | 뜻 |
|---|---|---|
| `(?=...)` | 긍정 룩어헤드 | 뒤에 이게 **있으면** |
| `(?!...)` | 부정 룩어헤드 | 뒤에 이게 **없으면** |
| `(?<=...)` | 긍정 룩비하인드 | 앞에 이게 **있으면** |
| `(?<!...)` | 부정 룩비하인드 | 앞에 이게 **없으면** |

**너비가 0이다.** 조건을 확인만 하고 매치 결과에는 포함되지 않는다.

비밀번호 규칙 같은 "여러 조건을 동시에" 에 자주 쓴다.

```js
// 8자 이상 + 숫자 포함 + 대문자 포함
/^(?=.*\d)(?=.*[A-Z]).{8,}$/
```

> 룩비하인드는 **자바스크립트가 2018년(ES2018)에야 들어왔다.**
> Safari 는 16.4(2023)부터다. 오래된 환경을 지원해야 하면 확인이 필요하다.

## 6. 자주 틀리는 지점

### 6.1 `\d` `\w` 는 유니코드가 아니다

```js
/^\d+$/.test("１２３")    // false — 전각 숫자
/^\w+$/.test("한글")      // false — \w 는 [A-Za-z0-9_] 다
```

`\w` 를 "단어 문자"로 이해하면 틀린다. **ASCII 만이다.**
한글을 다루려면 유니코드 속성을 쓴다.

```js
/^\p{Script=Hangul}+$/u.test("한글")    // true  (u 플래그 필수)
/^\p{L}+$/u.test("한글abc")             // true  (모든 글자)
```

Java 는 `Pattern.UNICODE_CHARACTER_CLASS` 플래그를 주면 `\w` 가 유니코드로 확장된다.

### 6.2 `.` 은 개행을 포함하지 않는다

```js
/a.b/.test("a\nb")     // false
/a.b/s.test("a\nb")    // true   — s(dotAll) 플래그
```

Java 는 `Pattern.DOTALL`, Python 은 `re.S`.

### 6.3 `$` 의 의미가 언어마다 다르다

```js
/^abc$/.test("abc\n")     // false  — JS 는 문자열 끝에서만
```

**Java·Python 은 여기서 true 다.** `$` 가 "끝, 또는 마지막 개행 앞"을 뜻한다.
정확히 문자열 끝만 원하면 Java 는 `\z`, Python 은 `\Z` 를 쓴다.

**보안 검증에서 이게 진짜 문제가 된다.**

```java
// ❌ "admin\n" 이 통과한다
if (input.matches("^[a-z]+$")) { ... }
// ✅
if (input.matches("\\A[a-z]+\\z")) { ... }
```

`m`(multiline) 플래그를 켜면 `^`/`$` 가 **줄마다** 걸리므로 더 위험해진다.

### 6.4 이스케이프해야 하는 문자

```
. ^ $ * + ? ( ) [ ] { } | \ /
```

사용자 입력을 정규식 **안에** 넣을 때는 반드시 이스케이프한다.

```js
const escape = (s) => s.replace(/[.*+?^${}()|[\]\\]/g, "\\$&");
new RegExp(escape(userInput));   // 안 하면 사용자가 패턴을 주입한다
```

Java 는 `Pattern.quote(s)` (`\Q...\E` 로 감싼다).

### 6.5 `g` 플래그와 `lastIndex` (JS 전용 함정)

```js
const re = /a/g;
re.test("abc");   // true
re.test("abc");   // false !   — lastIndex 가 남아 있다
```

`g` 플래그가 붙은 정규식 객체는 **상태를 가진다**.
재사용하는 정규식에 `g` 를 붙였다면 `re.lastIndex = 0` 을 하거나 매번 새로 만든다.
`String.matchAll` 을 쓰면 이 문제를 피한다.

## 7. 이 프로젝트와 이어지는 곳

| 여기서 배운 것 | 코드 |
|---|---|
| 백트래킹을 끊는 유일한 방법 | `lib/regexRunner.js` + `workers/regexWorker.js` — 1초 타임아웃 후 `terminate()` |
| 사용자 입력 이스케이프 | `/list-compare`·`/text` 등 사용자 문자열로 패턴을 만드는 곳 |
| 정규식 테스트·치환·그룹 확인 | `/regex` |

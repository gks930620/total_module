# dev-toolbox — 개발자 유틸 모음웹

Spring Boot(정적 서빙 전용) + React SPA 를 **단일 서버**로 배포하는 프로젝트.

> **AI 어시스턴트에게**: 이 README 가 이 저장소의 단일 진입점이다. 여기 적힌 규칙은
> 어떤 도구·환경에서 작업하든 그대로 따른다. 저장소를 처음 이어받았다면
> [`진행사항/인수인계.md`](진행사항/인수인계.md) 를 먼저 읽어라.

## 제품 개요

- **무엇**: 데이터 형식 변환·JWT 디코더·정규식 테스터부터 글자수·이미지·PDF 편집까지
  **웹 도구 37종**을 광고 없이 · 가입 없이 · 완전 한국어로 · **파일을 서버에 올리지 않고** 제공한다.
- **누구**: 한국 개발자(1차) · QA/기획/마케터(2차) · 일반 사용자(3차).
- **핵심 원칙**: **모든 도구가 예외 없이 브라우저 안에서만 동작한다**(NFR-02).
  이건 마케팅이 아니라 구조적 사실이다 — **서버 API 0개 / 데이터베이스 0개.** 입력을 받을 엔드포인트가 없다.
  CSP `connect-src 'none'` 이 fetch·XHR 을 브라우저 차원에서 차단해 이 약속을 강제한다.
  이 약속은 예외가 하나만 생겨도 무너지므로, 서버가 필요한 기능은 아무리 유용해도 넣지 않는다.

### 도구 37종 (라우트 41개 — `/json` `/yaml` `/csv` `/json-to-type` 는 별칭)

단일 출처는 `frontend/src/lib/tools.js`. **전수 설명은 `설계/03_도구카탈로그.md`.**

| 그룹 | 도구 |
|---|---|
| 데이터·포맷 | `/viewer`(별칭 `/json`) `/convert`(별칭 `/yaml` `/csv` `/json-to-type`) `/dummy` |
| 인코딩·보안 | `/base64` `/jwt` `/hash` `/uuid` `/escape` |
| 텍스트 | `/regex` `/diff` `/case` `/text` `/unicode` `/char-count` `/line-fix` `/list-compare` |
| 이미지·문서 | `/image` `/image-privacy` `/image-merge` `/favicon` `/pdf` |
| 계산·변환 | `/timestamp` `/cron` `/number-base` `/bytes` `/color` |
| 웹·네트워크 | `/url` `/cidr` `/qr` `/curl` `/utm` |
| 다이어그램 | `/erd` `/class-diagram` `/sequence` `/flowchart` `/state-diagram` `/diagram` |

**다이어그램 6종은 화면 하나를 나눠 쓴다** — `components/DiagramTool.jsx`. 종류마다 경로를 따로 둔 건
검색어가 서로 다르기 때문이다("ERD 그리기" ≠ "시퀀스 다이어그램"). `/erd` 와 `/class-diagram` 은
**CREATE TABLE·자바 소스를 붙여넣으면 그림이 나오고**, `/diagram` 을 뺀 5종에는 문법 없이 마우스로
그리는 **'그리기' 탭**이 있다(외부 라이브러리 없이 직접 만든 편집기). 상세: `설계/05_다이어그램.md`.

- **외부 런타임 의존성은 둘 뿐 — `pdf-lib`(`/pdf`) · `mermaid`(다이어그램 6종).**
  둘 다 **동적 `import()`** 로만 불러온다(`lib/pdfTools.js` · `lib/mermaidRender.js`) — 그 파일 밖에서는 절대 import 하지 않는다.
  mermaid 는 gzip 950KB 라 정적으로 넣으면 NFR-04 를 혼자 넘긴다.
- **도구 페이지는 전부 `React.lazy` 분할** — 첫 진입 gzip **72.8KB**(상한 200KB). Suspense 경계는 `ToolboxLayout` 의 `<main>`.
- **다크 모드** — 라이트·다크 토글(고른 적 없으면 OS 설정). `lib/theme.js`, 토큰은 `styles.css` 의 `:root[data-theme="dark"]`.

### 디자인 — 시안 J "Halo"

**"화려함을 한 곳에 모은다"**: ①읽는 면(카드·패널·본문)은 불투명 ②초점(히어로·주 버튼·활성 항목·아이콘 배지)에만
그라디언트 ③유리(blur)는 헤더에만 ④카드 윗변 1px 그라디언트 선. 라운드 20px, 버튼·칩은 알약형.
읽는 면의 경계는 `--edge` 한 줄 — 흰 면과 배경의 차이가 2% 뿐이라 그림자만으로는 안 보인다.

**단일 출처는 `frontend/src/styles.css` 의 `:root` 토큰** — 새 컴포넌트는 토큰만 조합해 만들고 색을 하드코딩하지 않는다
(하드코딩하면 다크 모드가 그 컴포넌트에서만 깨진다). 유일한 예외는 내보내기 파일 생성기
(`lib/canvas/exportSvg.js` 등) — 사이트 밖에서 열리므로 실색을 박는다. 상세: `설계/02_구조.md` §6.
**다른 프로젝트로 옮길 때는 `설계/디자인시안/halo-design-kit/` 폴더를 통째로 복사**(자기완결형 이식팩).

> 🔗 **라우트 추가·삭제 시 5곳을 함께 고친다**: `lib/tools.js` → `App.jsx` → `HomeController` → `SecurityConfig`
> → `public/sitemap.xml`. 백엔드 두 곳이 어긋나면 **운영에서만** 403 이 난다(로컬 재현 안 됨).
> 두 테스트가 잠근다: `frontend/src/lib/__tests__/tools.test.js`(5곳 전수 대조) ·
> `SpaRouteApiIntegrationTest`(실제 forward + SPA 산출물 존재 확인).

## 스택 / 저장소 구조

| 영역 | 스택 | 경로 | 테스트 |
|---|---|---|---|
| 백엔드 | Spring Boot 3.3.4 (Gradle, Java 17, `com.test.test`) — **클래스 5개**, DB·API 없음 | `src/` (루트가 곧 백엔드) | `./gradlew test` |
| 웹 | React 19 + Vite (JS) | `frontend/` | `npm test` / `npm run build` |
| 배포 | Railway 단일 컨테이너 | 절차: `설계/07_배포_Railway.md` | — |

### 로컬 실행

```bash
./gradlew bootRun        # → http://localhost:8082  (운영과 같은 형태. application-local.yml 에 8082 고정)
cd frontend && npm run dev   # → http://localhost:5173  (프론트 핫리로드 전용)
```

두 서버는 **서로 필요 없다**(서버 API 가 0개라서). 8082 는 **빌드된 SPA** 를 서빙하므로
프론트를 고쳤으면 `./gradlew copyFrontendBuild` 를 다시 돌려야 반영된다.

> 🔴 **배포 전 `./gradlew copyFrontendBuild` 필수** — Docker 이미지에는 node 가 없어 프론트 빌드가 skip 되고
> 커밋된 `src/main/resources/static` 을 그대로 패키징한다. 빠뜨리면 **빌드는 성공하는데 사이트가 빈 화면**이 된다.
> 그래서 `static/` 산출물은 **커밋 대상**이다(.gitignore 참조).

## 작업 방식 (TDD — 이 프로젝트의 핵심 규칙)

**항상 TDD다. 프로덕션 코드보다 테스트가 먼저다. 예외 없음.**

1. **테스트가 명세다** — 요구를 테스트로 먼저 쓴다(Red). 테스트 없이 구현으로 넘어가지 않는다.
2. **구현은 테스트를 통과시키는 것**(Green). 명세가 틀렸다고 판단되면 테스트를 고치는 게 아니라 되돌려 논의한다.
3. **로직은 `lib/` 순수 함수로** — 계산이 컴포넌트 안에 있으면 테스트에 렌더링 환경이 필요해진다.
   순수 함수면 Node 에서 그냥 호출해 검증할 수 있다 — 그래서 930건이 몇 초 안에 돈다.
4. **QA(실제 제품 시나리오 시험)가 완료 조건** — 개발자 테스트 재실행이 아니라 독립 관문이다.

## 이 프로젝트의 규칙

- **커밋·푸시·배포는 사용자가 명시적으로 요청할 때만.**
- **배포 전 조건**: 두 스택 테스트 통과 + QA 판정 통과 + `copyFrontendBuild` 실행.
- **새 라이브러리 도입은 그 자체로 결정 사항이다** — 외부 런타임 의존성 둘(pdf-lib·mermaid)을
  늘리는 일은 가볍게 하지 않는다. 무거운 것은 동적 `import()` 로 격리한다.
- **문서는 현재 상태만 적는다** — "무엇이 바뀌었다"는 이력을 문서에 쌓지 않는다(그건 git 커밋의 일).
- **기능을 걷어낼 때는 다섯 곳을 본다** — ①UI ②그 값을 읽는 분기 ③기본값 ④주석 ⑤문서.
  전수 점검에서 나온 결함이 거의 전부 이 모양이었다. 눈에 보이는 UI 만 지우고 나머지를 남기면
  기본값이 죽은 분기를 만들어 낸다.
- **수치는 세어서 확인한다.** 문서에 적힌 수치는 읽어서는 맞는지 알 수 없다.
  도구 수·테스트 수·번들 크기는 실제로 세거나 재고 나서 적는다.
- **코드 컨벤션**: `설계/06_코드컨벤션.md` — 문서와 코드가 어긋나면 문서가 기준이다.
- **금지**: 요청받지 않은 대규모 리팩터링, 요청 범위 밖 스택의 코드 수정.

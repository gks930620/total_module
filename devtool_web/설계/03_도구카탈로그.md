# 06. 도구 카탈로그 — 무엇이 있고 어떻게 만들었나

> **도구 37종 / 라우트 41개**
> 이 문서는 "지금 사이트에 실제로 있는 것" 의 전수 목록이다. 도구를 추가·삭제하면 여기도 함께 고친다.
> 도구 목록의 **단일 출처는 코드**(`frontend/src/lib/tools.js`)이며, 이 문서는 그 코드가 왜·어떻게 그렇게 됐는지를 설명한다.

### 이 프로젝트가 지키는 한 줄 원칙

> **모든 도구가 예외 없이 브라우저 안에서만 동작한다 (NFR-02).**

파일을 열든, 사진의 위치정보를 지우든, PDF 를 합치든 **네트워크로 나가는 요청이 한 건도 없다.**
이건 마케팅 문구가 아니라 구조적 사실이다 — 서버에 받을 API 자체가 없다.

## 1. 도구 하나가 만들어지는 방식 (공통 구조)

도구를 새로 만들 때마다 반복하는 4단계다. 37종 전부 이 틀을 따른다.

```
① lib/<도구>.js        순수 함수 (DOM·React 무관, 입력 → 출력)
② lib/__tests__/…      ①의 테스트를 먼저 작성 (TDD — 실패 확인 후 구현)
③ pages/<도구>Page.jsx 화면 (상태·입력·표시만. 계산은 전부 ①에 위임)
④ 등록 5곳             tools.js → App.jsx → HomeController → SecurityConfig → sitemap.xml
```

**왜 로직을 lib 으로 뺐나** — 계산이 컴포넌트 안에 있으면 테스트하려고 렌더링 환경(jsdom·testing-library)을 붙여야 한다.
순수 함수로 빼두면 Node 에서 그냥 호출해 검증할 수 있다. 그래서 930건이 몇 초 안에 돈다.

**등록 5곳은 자동으로 검증된다.** 백엔드 두 곳(HomeController·SecurityConfig)이 어긋나면
운영에서 그 URL 만 403 이 나는데, 로컬 개발 서버에서는 재현되지 않아 배포 후에야 발견된다.
그래서 두 방향으로 잠가 뒀다:

- `frontend/src/lib/__tests__/tools.test.js` — `tools.js` 의 41개 경로가 App.jsx·sitemap.xml·HomeController.java·SecurityConfig.java·백엔드 회귀 테스트에 **전부 있는지** 확인
- `src/test/java/…/SpaRouteApiIntegrationTest.java` — 42개 경로가 실제로 `index.html` 로 forward 되는지 확인

### 공통 컴포넌트

### 화면 디자인

**J "헤일로"** 시안 (10개 중 선정 — 근거는 `디자인시안/디자인_결정기록.md`).
핵심 규칙 네 가지: ① 읽는 면은 불투명 ② 그라디언트는 초점 한 곳에만 ③ 유리·블러는 헤더에만
④ 카드 상단 1px 그라디언트 라인. 토큰은 `frontend/src/styles.css` 의 `:root` 에 있다.

### 성능 — 라우트 단위 코드 분할

`App.jsx` 에서 도구 페이지를 전부 `React.lazy` 로 분리한다. 홈과 404 만 초기 번들에 들어간다.

| | 값 |
|---|---|
| 첫 진입 JS (gzip) | **63.5KB** (+ CSS 9.3KB) |
| 도구 페이지 청크 | 해당 URL 진입 시에만 · 대부분 2~4KB |
| pdf-lib 청크 (178KB gzip) | `/pdf` 에서 실제 작업 시작 시에만 |

도구 전부를 정적 import 하면 초기 번들이 예산(200KB) 언저리까지 커진다 — 그래서 전 페이지 lazy 분할이다.
분할하지 않을 이유가 없고, 무엇보다 `/json` 하나 쓰러 온 사람이 PDF 라이브러리를 받을 이유가 없다.

## 2. 데이터 · 포맷 (3종)

### `/viewer` — 데이터 뷰어 (별칭 `/json`)
- **무엇** JSON·YAML·CSV·TSV·마크다운 표를 붙여넣으면 **트리 · 표 · 정렬된 원문** 세 가지로 본다.
- **왜 다시 만들었나** 한 번 지웠다가 되살린 도구다. "포매터가 있으니 뷰어는 필요 없다" 고 봤는데,
  실제로 써 보니 **입력칸 너비를 넘어가는 순간 정렬된 JSON 도 읽기 어렵다**. 접었다 펴는 게 핵심이었다.
- **읽는 일은 변환기가 한다** `lib/dataView.js` 는 `convert.js` 의 `parseInput` 을 그대로 쓴다.
  파서를 두 벌 두면 형식이 하나 늘 때마다 두 곳을 고쳐야 한다 — 뷰어는 읽어낸 **값**만 다룬다.
- **트리는 한 번 눕혀서 그린다** 재귀 구조를 그대로 렌더하지 않고 `flattenValue` 로 행 배열을 만든다.
  가상 스크롤이 "보이는 행만" 그리려면 펼쳐진 전체 목록이 배열이어야 하기 때문이다.
  워커 없이 메인 스레드에서 눕히므로 **5만 노드 상한**을 두고, 넘치면 잘랐다고 알린다 —
  조용히 일부만 보여 주면 사용자는 데이터가 그것뿐인 줄 안다.
- **검색은 트리가 직접 소유한다** 부모와 상태를 주고받으면 effect 로 동기화해야 하고 렌더가 연쇄된다.
  커서는 `searchKey` 에 종속시켜 렌더 중에 판별한다(React 19 `set-state-in-effect` 규칙을 끄지 않는 방법).
- **`/json` 이 여기로 온다** "json 뷰어"·"json 포매터" 로 들어오는 사람이 원하는 건 변환이 아니라 보기다.

### `/convert` — 데이터 형식 변환 (별칭 `/yaml` `/csv` `/json-to-type`)
- **무엇** JSON · YAML · CSV · TSV · 마크다운 표를 서로 바꾸고, SQL INSERT · TypeScript · Java · Kotlin 타입 코드로 내보낸다.
- **N×M 을 N+M 으로** 형식 쌍마다 변환기를 두면 조합이 폭발한다. 그래서 가운데에 **정규 JS 값**을 두고
  `입력 → 파서 → JS 값 → 직렬화기 → 출력` 한 방향으로만 흐르게 했다(`lib/convert.js`).
  형식을 하나 더 붙이는 비용이 파서 1개 + 직렬화기 1개다.
- **표 정보는 잃지 않는다** CSV → 마크다운 표처럼 표에서 표로 갈 때는 파서가 넘긴 `table`(원본 열 순서)을
  그대로 물려준다. JS 값으로만 옮기면 객체 키 순서에 기대게 돼 열 순서가 흔들린다.
- **JSON → JSON 은 포매터로도 쓸 수 있다** 들여쓰기는 3칸으로 정해 뒀다.
- **고르게 두지 않는 것들** 들여쓰기·테이블명·루트 타입명은 화면에서 뺐다.
  칸 셋이 도구 막대를 차지하면서 정작 자주 쓰는 형식 선택을 밀어냈는데,
  **이름은 붙여넣은 자리에서 고치는 편이 빠르다**(에디터의 이름 바꾸기가 훨씬 낫다).
  `sample`·`Root` 로 고정하고 라이브러리는 여전히 아무 값이나 받는다.
  **DB 만 남긴다** — 식별자 인용·불리언 표기가 방언마다 달라 나중에 손으로 고치기 어렵다
  (예약어 컬럼은 인용 없이는 아예 안 돈다).
  다만 **읽으려고** 들어온 사람은 `/viewer` 로 보낸다 — 넓은 화면에서 접었다 펴는 게 낫다.
- **붙여넣으면 형식을 알아본다** `{`→JSON, `|`→마크다운 표, 탭·쉼표로 열이 맞으면 TSV·CSV, `키:`→YAML.
  틀리면 사용자가 고르면 되므로, 애매할 때는 바꾸지 않고 그대로 둔다.
- **표가 필요한 출력** CSV·TSV·마크다운·SQL 은 객체(또는 객체의 배열)여야 만들 수 있다. 값 하나뿐이거나
  배열 안의 모양이 제각각이면 변환을 시도하지 않고 왜 안 되는지 알려 준다.
- **중첩은 JSON 문자열로 담고, 담았다고 알린다** 표의 한 칸에는 값 하나만 들어가므로
  `{"KK":[{"c1":"d2"}]}` 의 `KK` 는 `'[{"c1":"d2"}]'` 가 된다. **거부하지 않는 이유**는
  ①되돌리면 원본이 나오는 무손실 변환이고 ②JSON·JSONB 컬럼에는 이게 정확히 맞는 리터럴이며
  ③"거의 평평한데 한 필드만 중첩"이 가장 흔한 경우라 거부하면 도구가 안 쓰이기 때문이다.
  평탄화(`KK.0.c1`)는 원소마다 모양이 다르면 열이 폭발해서 택하지 않았다.
  다만 조용히 하지는 않는다 — 어떤 열이 눌렸는지 화면에 알린다.
- **URL 이 3개인 이유** 화면은 하나지만 `/yaml`·`/csv`·`/json-to-type` 은 살려 뒀다.
  검색 유입이 유일한 획득 경로(기획서 §6)이고 "마크다운 표 만들기"와 "dto 생성기"는 서로 다른 검색어다.
  각 URL 은 자기 제목·설명·키워드를 갖고 시작 형식만 다르게 열린다 — `/base64`·`/jwt` 와 같은 방식.
  홈 카드에는 `/convert` 하나만 보인다.
- **SQL INSERT 는 타입을 지킨다** 표의 셀을 전부 문자열로 만들면 `null` 이 빈 문자열이 되고
  숫자·불리언에 따옴표가 붙는다(둘 다 실제로 INSERT 를 깨뜨린다 — `''` 는 NULL 이 아니고
  `'30'` 은 INT 컬럼에서 거부될 수 있다). 그래서 `fromJsonRows` 가 표시용 문자열과 함께
  **원본 값(`raw`)** 을 넘기고, SQL 직렬화기가 그걸 쓴다. CSV 처럼 타입이 없는 표는
  `coerceCell` 로 되살린다 — 빈 칸은 NULL 로 보되 **앞자리 0 은 문자열로 남긴다**(사번·우편번호).
- **식별자는 방언 규칙대로 감싼다** 안 감싸면 `order` 같은 예약어에서 문법 오류가 나고,
  PostgreSQL 에서는 대문자 컬럼명이 소문자로 접혀 "없는 컬럼"이 된다.
  예전에는 공백이 든 컬럼명을 `my_col` 로 **조용히 바꿔** 대상 DB 에 없는 이름을 만들었다.
  인용·불리언 표기 규칙의 단일 출처는 `lib/sqlDialect.js` 이고 `/dummy` 와 같은 표를 쓴다 —
  따로 두면 반드시 어긋난다(실제로 어긋나서 합쳤다).
- **만든 것을 자기가 다시 읽을 수 있어야 한다** 전수 점검(입력 5 × 출력 10 + 값 종류별 왕복)에서
  구분자를 그대로 흘려보내는 곳이 여럿 나왔다. 지금은 형식마다 이렇게 막는다:
  | 형식 | 흘리면 깨지는 것 | 처리 |
  |---|---|---|
  | 마크다운 표 | 셀 안의 `|` | `\|` 로 이스케이프 — 안 하면 **열이 하나 늘어난다** |
  | 마크다운 표 | 셀 안의 줄바꿈 | GFM 관례대로 `<br>` — 표는 한 줄이 한 행이다 |
  | YAML | 값 안의 탭 | 인용하고 `\t` 로 이스케이프 — 안 하면 우리 파서가 우리 출력을 거부한다 |
  | CSV·TSV | 구분자·따옴표·줄바꿈·**앞뒤 공백** | 따옴표로 감싼다 |
  | SQL | 홑따옴표 | `''` (표준). 문자열 안의 줄바꿈은 유효한 SQL 이라 그대로 둔다 |
  | 타입 코드 | `2nd` `a@b` 같은 키 | 쓸 수 있는 식별자로 다듬고 원래 키는 애너테이션으로 남긴다 |
- **CSV 의 공백은 따옴표가 가른다**(RFC 4180) `"  x  "` 의 공백은 값이고,
  따옴표 없는 `  x  ` 의 공백은 사람이 보기 좋으라고 넣은 것이다(손으로 쓴 `a, b, c`).
  그래서 인용된 칸만 그대로 두고 나머지는 다듬는다. 예전엔 일괄로 다듬어 **지켜 온 공백까지 지웠다**.
- **형식 자체의 한계는 못 넘는다** CSV·TSV·마크다운에는 타입이 없어 문자열 `"null"` 은 다시 읽으면 NULL 이
  되고, 마크다운 표는 칸을 정렬하느라 앞뒤 공백을 지킬 수 없다. 이건 고칠 수 있는 버그가 아니라
  그 형식의 성질이라 그대로 둔다 — 값을 그대로 지켜야 하면 JSON·YAML 로 내보내면 된다.
- **YAML 의 탭 검사는 들여쓰기에만 건다** 탭이 금지된 건 들여쓰기지 인용된 문자열 안이 아니다.
  전에는 탭이 든 줄을 통째로 거부해서 남이 만든 정상 YAML 도 못 읽었다.
- **타입 코드 출력** 값을 재귀 순회해 타입 트리를 만들고 중첩 객체는 별도 타입으로 승격한다.
  Java 는 **Lombok class 와 record 둘 다** 낸다. 이 프로젝트의 DTO 규칙(`code-convention` §0)은 class 지만,
  이 도구를 쓰는 사람의 규칙까지 정해 줄 이유는 없다 — 불변 응답 타입에는 record 가 짧다.
- **한국어 처리** 마크다운 표는 한글의 표시 폭이 2 라 원문 정렬이 어긋난다. CJK 를 2 로 세어 패딩한다.
- **타입 추론** CSV → JSON 에서 숫자·불리언·null 을 캐스팅하되 **앞자리 0 이 있는 값(사번·우편번호)은 문자열로 둔다.**
- **YAML 은 직접 만든 파서**(`lib/yaml.js`, 외부 라이브러리 없음). 지원 범위를 실무에서 쓰는 부분집합으로 명시적으로 한정했다 — 매핑·시퀀스·중첩·인용 문자열·flow 표기·주석·문서 구분자(`---`)·블록 스칼라(`|`, `|-`, `>`, `>-`). **미지원**은 앵커/별칭(`&`,`*`)·태그(`!!`)·복합 키. 문서에 적어 두고 화면에도 안내한다.

### `/dummy` — DB 더미데이터 생성기
- **무엇** 쓰는 DB 를 고르고 컬럼을 정의하면 그 DB 에 바로 넣을 수 있는 `data.sql` 을 만든다.
- **범위를 좁힌 것이 설계의 핵심** "테스트 데이터 일반"이 아니라 **DB 더미데이터 전용**이다.
  넓게 잡았을 때는 "타입"이 생성기(이름·이메일)이면서 컬럼 타입인 척을 해 개념이 꼬였다.
  - **MySQL 의 `TINYINT(1)` 은 불리언으로 본다** — `BOOLEAN` 이 실제로 이것의 별칭이라 관례상 0/1 이다.
    폭이 1 이 아닌 `TINYINT` 는 그냥 정수로 둔다
  - `NOT NULL` 이 없는 컬럼은 NULL 을 허용한다는 뜻이므로 **NULL % 를 10 으로** 잡아 값에도 섞는다
  - PostgreSQL·Oracle 의 별도 `COMMENT ON COLUMN` 문도 읽어 비고를 채운다
- **길이는 방언마다 뜻이 다르다** MySQL·PostgreSQL 의 `VARCHAR(n)` 은 n **글자**지만
  Oracle `VARCHAR2(n)` · SQL Server `VARCHAR(n)` 은 n **바이트**다(한글은 UTF-8 로 3바이트).
  바이트 기준 방언에서는 글자 수 상한을 나눠 계산하고, 한 글자도 못 담는 길이면 1바이트 문자로 떨어뜨린다 —
  빈 문자열을 내면 `NOT NULL` 컬럼에서 쓸모가 없다.
- **문자열 기본은 영문+숫자다** 한글 음절을 무작위로 뽑으면 "쎍옠씵쀪" 같은 글자가 나온다.
  더미데이터로 못 쓸 건 없지만 눈으로 훑기 어렵다. 한글이 필요하면 컬럼마다 골라 쓴다.
- **있는 스키마에서 컬럼을 가져온다** 테이블의 모양이 DDL 로만 오지는 않는다. 그래서 아래를 모두 읽는다:
  | 붙여넣는 것 | 읽어내는 것 |
  |---|---|
  | `CREATE TABLE` | 컬럼명·타입·길이·`NOT NULL`·주석 |
  | `INSERT INTO … VALUES` | 컬럼명 + 첫 튜플 값으로 타입 추론 |
  | **JPA 자바 엔티티** | `@Table`·`@Column(name·length·precision·scale·nullable)`·`@Id`·`@Enumerated`, camelCase → snake_case |
  | **Kotlin data class** | 주 생성자 프로퍼티 + 본문 프로퍼티, `Type?` 는 NULL 허용 |
  | **TypeScript interface** | `name?: type`, 유니온의 `null`·`undefined`, 배열 → JSON 컬럼 |
  | **JSON** | 값에서 타입 추론. 앞 행이 `null` 이면 뒤 행에서 채운다 |
  | **CSV** | 헤더가 컬럼명, 데이터 행이 타입 근거. 구분자·BOM 자동 처리 |
  - **JPA 를 쓰면 엔티티가 곧 스키마다.** 그래서 `@ManyToOne`·`@OneToOne` 은 `@JoinColumn` 이름의
    **FK 컬럼**으로 바꾸고, `@OneToMany`·`@ManyToMany` 는 반대편 테이블 것이라 컬럼으로 만들지 않는다.
    `@Transient`·`static` 필드도 뺀다. FK 의 타입은 상대 PK 를 알 수 없어 `BIGINT` 로 두고 **경고를 남긴다**.
  - **메서드 본문의 지역변수를 컬럼으로 착각하지 않는다.** 중괄호 깊이를 세어 클래스 본문의 최상위 문장만 읽는다
    (정규식만으로 하면 `getXxx()` 안의 `String prefix = …` 가 컬럼이 된다).
  - **판별은 내용으로 한다.** 다만 `SELECT … ;` 같은 다른 SQL 문은 세미콜론 때문에 2열짜리 CSV 로 보이므로 먼저 걸러낸다.
- **컬럼 순서는 끌어서 바꾼다.** 손잡이(⠿)를 누르는 동안에만 행이 draggable 이 된다 —
  항상 걸어 두면 입력칸에서 텍스트를 선택할 수 없다. 손잡이에 포커스를 두고 화살표 키로도 옮길 수 있다(NFR-09).
- **빈 컬럼 한 줄로 시작한다.** 예시 스키마를 기본으로 깔아 두면 사용자가 정의한 것처럼 보인다.
- **상한 500행** 성능 한계가 아니라(500행 × 10컬럼 ≈ 1~2ms) 실수로 거대한 파일을 만들지 않게 둔 값이다.
- **의도적으로 안 만든 것** **주민등록번호는 생성하지 않는다.** 형식이 유효한 주민번호를 대량 생성하는 기능은 실익보다 오남용 위험이 크다고 판단했다.

## 3. 인코딩 · 보안 (5종)

### `/base64` — Base64 인코더 · 디코더
- **무엇** UTF-8 안전 Base64 인코딩·디코딩, URL-safe 변형.
- **방향을 패널 사이에 둔다** 위에 인코드/디코드 토글을 두면 "지금 뭘 하는 중인지" 를 따로 읽어야 한다.
  대신 패널 이름이 `입력 · 문자` → `출력 · Base64` 로 바뀌고, 사이의 화살표 버튼이 방향을 말한다.
  누르면 뒤집히면서 **지금 결과가 다음 입력이 된다** — 인코드한 값을 바로 되돌려 볼 수 있다.
- **URL-safe 는 인코드에만 있다** 차이는 셋이다: `+`→`-`, `/`→`_`, 그리고 **패딩 `=` 제거**.
  앞의 둘보다 마지막이 더 자주 사고를 낸다(엄격한 디코더는 패딩이 없으면 거부한다).
  디코딩은 `-` `_` 를 되돌리고 패딩을 다시 채우므로 **고를 것이 없다** — 그래서 선택칸을 안 보여 준다.

### `/jwt` — JWT 디코더 · 생성기
- **무엇** 토큰을 풀어 header·payload·클레임을 보여 주고(`exp`·`iat`·`nbf` 는 한국 시간), **키로 서명을 검증**하고, 반대로 **토큰을 만든다**. 알고리즘 11가지 전부.
- **표준 클레임에 뜻을 붙인다** `sub` `aud` `nbf` 는 이름만 봐서 알 수 없다(RFC 7519 §4.1).
- **서명을 검증한다** 비밀키를 넣으면 그 키로 만들어진 토큰인지 확인한다(`lib/jwt.js`, Web Crypto HMAC).
  화면은 **넣는 것은 왼쪽, 나온 것은 오른쪽** 하나로 통일했다 — 읽기 탭은 왼쪽에 토큰·서명키·서명 확인,
  오른쪽에 Header·Payload. 생성 탭은 왼쪽에 Header/Payload·비밀키, 오른쪽에 만들어진 토큰만 둔다.
- **안 맞을 때 먼저 볼 곳을 짚어 준다** 서명 실패의 상당수는 값이 틀린 게 아니라 **눈에 안 보이는 공백**이다.
  키 앞뒤·가운데 공백, 토큰 가운데 줄바꿈, base64 해석 차이를 찾아 문장으로 알려 준다(`signatureHints`).
  값을 말없이 고치지는 않는다 — 공백이 진짜 키의 일부일 수도 있다.
  암호 연산은 브라우저 내장에 맡긴다 — 직접 구현하지 않는 원칙은 `/hash` 와 같다.
  **이걸 제공할 수 있는 이유가 이 프로젝트의 존재 이유다** — 비밀키가 브라우저 밖으로 나가지 않는다.
  (예전엔 "비밀키를 웹 도구에 붙여넣게 하는 건 위험하다" 며 뺐는데, 그건 **서버로 보내는 도구**에나 맞는 논리였다.)
- **결과를 셋으로 가른다** 맞다 / 틀리다 / **확인할 수 없다**.
  RS256 토큰에 "서명이 맞지 않습니다" 라고 하면 위조라는 뜻으로 읽히는데, 사실은 우리가 아직 못 다루는 것뿐이다.
- **토큰을 만든다** header·payload 를 고쳐 HS256·384·512 로 서명한다. `exp` 는 "1시간·1일" 버튼으로 넣는다 —
  Unix 초를 손으로 계산할 사람은 없다.
- **비밀키를 무엇으로 읽나** 같은 글자라도 **문자로 쓸 때와 base64url 바이트로 쓸 때 서명이 완전히 달라진다.**
  jwt.io 의 "Base64URL Encoded" 체크가 이것이고, 켜 둔 줄 모르고 "검증 실패" 를 보는 일이 흔하다.
  그래서 우리는 이 선택을 비밀키 칸 바로 옆에 늘 보이게 뒀다.
- **⚠️ 헤더의 키 순서가 서명을 바꾼다** 서명 대상은 인코딩된 **문자열**이라, 사용자가 쓴 헤더를 재배열하면
  같은 내용인데 다른 토큰이 나온다. 만들 때 없는 항목만 뒤에 채우고 순서는 건드리지 않는다.
  (처음엔 `typ` 를 앞으로 밀어 넣어 jwt.io 와 값이 달랐다.)
- **11가지를 모두 다룬다** HS256·384·512(비밀키) · RS·PS·ES(공개키 쌍). PEM(PKCS#8 개인키 / SPKI 공개키)을
  받아 `importKey` 하고, 없으면 **키쌍을 그 자리에서 만들어 준다**(RSA 2048 · EC P-256/P-384) —
  openssl 을 꺼내 오게 하면 사용자는 거기서 멈춘다.
- **검증에 개인키를 넣어도 받아 준다** 개인키만 들고 있는 경우가 흔하다. 공개키를 뽑아내는 표준 API 가 없어서,
  같은 내용을 다시 서명해 비교하는 방식으로 처리한다.
- **ECDSA 서명은 raw(r‖s)** Web Crypto 가 내는 형식이 JWS 가 요구하는 형식과 같아 그대로 쓴다.
  서버 라이브러리 중에는 DER 을 쓰는 것이 있어 값이 달라 보일 수 있다.
- **시각도 함께 본다** 서명이 맞는 것과 지금 써도 되는 것은 다른 문제다. `exp`·`nbf`·`iat` 를 확인해
  "서명은 맞지만 만료됐다" 를 구분해 말한다(시계 오차 60초는 봐 준다).

### `/hash` — 해시 생성기 · HMAC
- **무엇** SHA-1/256/384/512, MD5, CRC32. 텍스트와 **파일** 모두. **HMAC** 과 **기대값 대조**까지.
- **키를 넣으면 HMAC 이 된다** 탭으로 가르지 않았다 — 하는 일이 "이 데이터의 지문" 으로 같고,
  탭을 가르면 키를 넣을 수 있다는 것 자체를 모른다. 웹훅 서명 검증(Stripe·GitHub 등)이 전부 이것이다.
  MD5·CRC32 는 없다 — Web Crypto 가 HMAC 에 SHA 계열만 허용한다.
- **진짜 쓰임은 대조다** "값을 만드는 것" 보다 **"남이 준 값과 같은가"** 가 이 도구를 여는 이유다.
  64자 16진수 두 줄을 눈으로 맞추게 두면 사람이 틀린다. 기대값을 붙여넣으면 어느 알고리즘과 맞는지 짚어 주고,
  틀렸을 때는 **길이로 무엇을 기대한 값인지** 알려 준다(원인을 좁혀 준다).
  붙여넣는 형태가 제각각이라 `sha256sum` 의 "해시  파일명", certutil 의 두 자리 공백, 콜론 구분을 모두 받아 준다.
- **파일은 다시 읽지 않는다** 키를 고칠 때마다 파일을 다시 고르게 할 수는 없어 바이트를 들고 재계산한다.
- **어떻게** SHA 계열은 브라우저 내장 **WebCrypto(SubtleCrypto)** — 직접 구현하지 않는다(검증된 구현을 쓰는 게 안전하다). WebCrypto 가 지원하지 않는 MD5·CRC32 만 직접 구현했다. 파일은 드래그&드롭으로 받아 `ArrayBuffer` 로 해시한다.

### `/uuid` — UUID / ULID 생성기
- **무엇** UUID v1 · v3 · v4 · v5 · v7, ULID, NIL 을 원하는 개수만큼. + UUID 분석.
- **v7 은 한 번에 뽑아도 시간순이다** 타임스탬프가 ms 단위라 100개를 한 번에 만들면 대부분 같은 ms 에
  들어가는데, 그 아래를 전부 난수로 채우면 **그 사이 순서가 무작위**가 된다.
  이 도구는 개수를 받아 한 번에 만드는 도구라 화면의 목록이 이미 안 정렬돼 있었다 —
  "정렬되는 UUID" 라는 존재 이유가 정작 화면에서 깨져 있었다.
  RFC 9562 §6.2 "Method 1" 대로 `rand_a` 12비트를 카운터로 쓴다.
- **이름 기반(v3·v5)** 같은 이름에서 **언제 어디서나 같은 UUID** 가 나온다. 그게 요점이라,
  개수를 3으로 두면 같은 값이 세 개 나온다(버그가 아니다). RFC 4122 네임스페이스 넷을 고를 수 있다.
- **v1 의 노드 ID** 원래는 MAC 주소지만 **브라우저는 MAC 을 알 수 없다.**
  RFC 9562 §5.1 이 정한 대로 무작위 노드를 쓰되 **멀티캐스트 비트를 세워** "진짜 MAC 이 아니다" 라고 표시한다.
- **v5 의 SHA-1 은 동기 구현이다** 보통은 Web Crypto 에 맡기지만(그게 원칙이다) 비동기로 만들면
  `generateMany` 부터 화면 렌더까지 전부 비동기가 된다. MD5 를 직접 구현한 것과 같은 사정이고,
  RFC 기준값(100만 바이트 벡터 포함)을 테스트가 고정한다. **보안 목적으로는 쓰지 않는다.**
- **어떻게** 난수는 전부 `crypto.getRandomValues` (CSPRNG). `Math.random` 은 쓰지 않는다. v7 은 상위 48비트에 밀리초 타임스탬프를 넣어 **시간순 정렬이 되는** UUID 다(DB 인덱스 친화적). ULID 는 Crockford Base32.

### `/escape` — 문자열 이스케이프
- **무엇** JSON·SQL·HTML·정규식·유닉스 셸용 이스케이프와 그 역변환.
- **어떻게** 각 대상별 치환표. HTML 엔티티는 디코딩도 지원한다 — 이때 `&nbsp;` 는 **U+00A0** 으로 되돌린다(U+0020 이 아니다. 이걸 틀리면 붙여넣은 코드가 미묘하게 깨진다).

## 4. 텍스트 (8종)

### `/regex` — 정규식 테스터
- **⚠️ 매칭은 워커에서 돈다.** `(a+)+$` 같은 패턴은 한 번의 `exec()` 안에서 지수적으로 되짚는다
  (치명적 백트래킹·ReDoS). 실측으로 **167초** 동안 탭이 얼어붙었다 —
  자바스크립트는 실행 중인 정규식을 중단할 방법이 없어서 setTimeout 도 AbortController 도 소용없다.
  **다른 스레드에서 돌리고 죽이는 것**이 유일한 해결책이라 워커를 쓴다(1초 넘으면 terminate).
  죽인 뒤에도 다음 실행은 정상이다 — 한 번 멈췄다고 도구가 못 쓰게 되면 안 된다.
- **무엇** 패턴과 대상 문자열로 매치와 캡처 그룹을 본다. 플래그는 `g` 고정이다 — 체크박스 5개를 두었더니 대상에 대문자·줄바꿈·이모지가 없으면 켜도 결과가 같아 고장난 것처럼 보였다. 조절이 필요하면 패턴 안에 쓴다(`[Hh]ello` · `[sS]`).
- **어떻게** **무한루프 방지 장치**가 핵심이다. `g` 플래그에서 길이 0 매치가 나오면 `lastIndex` 를 강제로 전진시킨다(안 그러면 브라우저가 멈춘다). 매치 수도 1000건에서 끊고 "잘렸음" 을 표시한다.

### `/diff` — 텍스트 비교
- **무엇** 두 텍스트의 줄 단위 차이를 좌우로 본다.
- **어떻게** 줄 단위 **LCS(최장 공통 부분수열)**. 긴 입력에서 O(n·m) 메모리가 터지지 않도록 앞뒤 공통 구간을 먼저 잘라내고(대부분의 실제 diff 는 이걸로 크게 줄어든다) 셀 수를 400만(≈2000×2000)으로 상한을 뒀다.
- **화면** IDE 의 "Compare With" 처럼 **좌우로 마주 놓는다**(`toSideBySide`). unified 목록으로 늘어놓으면 바뀐 줄이 위아래로 흩어져 무엇이 무엇으로 바뀌었는지 안 보인다 — 이어진 삭제·추가 묶음을 순서대로 짝지어 같은 행에 놓는다.

### `/case` — 케이스 변환
- **무엇** camelCase ↔ snake_case ↔ kebab-case ↔ PascalCase ↔ CONSTANT_CASE 등 12가지 표기법.
- **화면** 넣는 것은 왼쪽, 나온 것은 오른쪽. 오른쪽 패널 머리에서 표기법을 고른다(데이터 뷰어와 같은 배치).
- **어떻게** 입력을 먼저 "단어 배열" 로 정규화한 뒤 각 형식으로 다시 조립한다. Java camelCase → DB snake_case → URL kebab-case 를 오가는 스택 간 이동이 실제 사용 시나리오다.

### `/text` — 텍스트 정리
- **무엇** 줄 정렬·번호 매기기·접두/접미 붙이기·빈 줄 제거·양끝 공백 제거.
- **어떻게** 줄 단위 연산 조합. 한국어 정렬은 `Intl.Collator("ko")` 로 한다(코드포인트 순서와 다르다).
- **화면** 원본은 왼쪽에 그대로 두고, **켜진 작업만 순서대로 적용해** 오른쪽에 낸다. 예전에는 버튼이 입력 칸을 그 자리에서 갈아치워 되돌릴 수 없었다 — 잘못 누르면 붙여넣은 원본이 사라졌다.

### `/unicode` — 유니코드 · 한글 분석
- **무엇** 문자별 코드포인트·UTF-8 바이트·이스케이프 표기, 한글 초·중·종성 분해/조합.
- **어떻게** 한글은 유니코드 완성형 공식(`(초×21+중)×28+종+0xAC00`)으로 분해·조합한다. **보이지 않는 문자**(제로폭·NBSP)를 눈에 보이게 표시하는 게 실전 가치의 절반이다 — 붙여넣기 사고의 주범이다.

### `/char-count` — 글자수 세기
- **세는 방법이 셋이고 값이 다르다** 👨‍👩‍👧 하나가 UTF-16 길이 8 · 코드포인트 5(이모지 3 + ZWJ 2) ·
  **사람 눈에는 1** 이다. 예전에는 코드포인트를 "graphemes" 라고 불러 5 를 내놓았다 — 그냥 틀린 답이다.
  `Intl.Segmenter` 로 유니코드 규칙대로 끊어 센다. 셋이 갈릴 때(= 이모지가 있을 때)만 화면에서 알린다.
- **무엇** 공백 포함/제외 글자수, 단어·줄·문단 수, 원고지 매수, UTF-8 바이트, SNS·서식별 제한 대비.
- **어떻게** `chars`(UTF-16 길이)와 `graphemes`(`Array.from` — 이모지를 1로) 를 **구분해서** 센다. 원고지는 200자=1매 관례. `LENGTH_LIMITS` 로 SMS 90바이트·트위터 280자·자소서 항목 등에 대한 잔여량을 같이 보여준다.
- **덤** 보이지 않는 공백(제로폭·NBSP·행말 공백)의 개수를 따로 센다. 자소서 글자수가 안 맞는 이유가 대개 여기 있다.

### `/line-fix` — 줄바꿈 정리
- **무엇** PDF·논문에서 복사하면 줄마다 끊기는 텍스트를 원래 문단으로 되돌린다.
- **어떻게** 문단 경계(빈 줄)와 목록(`- * • 1. >`)은 유지하고 그 안의 줄바꿈만 잇는다.
- **개발 중 잡은 버그** 처음엔 줄을 그냥 이어붙였는데, 한국어에서 "안녕하세" + "요" 가 아니라 "**단어** " + "**단어**" 로 끊기는 경우가 대부분이라 공백 없이 붙으면 단어가 뭉친다. → **양쪽이 모두 CJK 표의문자/가나일 때만** 공백 없이 붙이고, 그 외에는 공백을 넣도록 고쳤다. 테스트가 잡아낸 실제 결함이다.

### `/list-compare` — 목록 대조
- **무엇** 명단 두 개의 교집합·차집합·합집합·중복을 찾는다. 엑셀 VLOOKUP 대용.
- **어떻게** `Set` 연산. 옵션으로 대소문자 무시·공백 정리·정렬을 건다. 결과는 세 칸(양쪽/A만/B만)으로 나눠 보여주고 각각 복사할 수 있다.
- **`/diff` 와의 차이** 순서를 보지 않는다. `/diff` 는 몇 번째 줄이 어떻게 바뀌었나(코드·설정), 이쪽은 어느 쪽에만 있나(명단·사번). 순서가 뒤섞인 명단을 `/diff` 로 보면 옮겨진 줄까지 전부 삭제+추가로 잡힌다. **엑셀 VLOOKUP 을 대신하는 자리**다.

## 5. 이미지 · 문서 (5종)

이 그룹은 "**웹에 올리면 안 되는 파일을 다루는 도구**" 라는 문제의식에서 나왔다.
이력서·계약서 PDF, 가족사진, 사업 자료를 낯선 사이트에 업로드하는 게 지금 표준 관행인데, 그럴 이유가 없다.

### `/image` — 이미지 리사이즈 · 변환
- **무엇** 크기 줄이기·압축·JPG/PNG/WebP 변환·회전. **여러 장 한 번에.**
- **어떻게** Canvas API. `createImageBitmap` → 캔버스에 리샘플 → `canvas.toBlob(type, quality)`. 크기 계산(`computeSize`)은 비율 유지·긴 변 기준·정확한 px·mm→px(인쇄 DPI) 를 지원한다.
- **덤** 여권/증명사진 규격(`PHOTO_SPECS`)을 프리셋으로 넣었다 — 3.5×4.5cm 를 300DPI 로 뽑으면 몇 px 인지 매번 찾아보게 되는 값이다.

### `/image-privacy` — 사진 개인정보 지우기
- **무엇** 사진의 촬영 위치(GPS)·기기 정보를 **확인하고 제거**하고, 가릴 부분을 모자이크로 덮는다.
- **어떻게** EXIF 파서를 직접 작성했다(`readExif` — JPEG APP1 마커 → TIFF 헤더 → IFD 순회 → GPS IFD 의 도분초를 십진 좌표로). GPS 가 있으면 **지도 링크와 함께 경고**를 띄운다.
- **제거 방식** Canvas 로 다시 그려 저장한다. 이 과정에서 EXIF·GPS·기기 정보가 **전부** 사라진다 — 화면에 보이는 픽셀만 남는다.
- **모자이크가 블러보다 안전하다** 약한 블러는 복원 시도가 가능하다는 연구가 있다. 그래서 기본값을 모자이크로 두고, 블러를 고르면 화면에 경고를 띄우며, "검게 칠하기" 를 함께 제공한다. 모자이크는 블록 평균색으로 픽셀을 **덮어써서** 복원이 불가능하다.

### `/image-merge` — 이미지 이어붙이기
- **무엇** 캡처 여러 장을 세로·가로로 한 장으로 잇는다.
- **어떻게** 크기가 다른 이미지는 가장 좁은 쪽에 맞춰 축소·정렬한다(끄면 원본 크기 배치 + 배경색 채움). 순서는 ↑↓ 로 바꾼다.

### `/favicon` — 파비콘 생성 · 색 추출
- **무엇** 로고 하나로 16·32·48·180·192·512 파비콘을 만들고 HTML 삽입 코드까지 준다.
- **어떻게** 정사각형 가운데 크롭 후 크기별 렌더. 배경(투명/흰색/검정) 선택 가능.
- **덤** 이미지의 대표 색 6개를 뽑는다(`extractPalette` — RGB 를 양자화해 빈도순). `<meta name="theme-color">` 값으로 바로 쓸 수 있다.

### `/pdf` — PDF 편집
- **무엇** 합치기 · 나누기·범위 추출 · 이미지→PDF · 메타데이터 제거.
- **어떻게** **유일하게 외부 런타임 라이브러리를 쓴다 — `pdf-lib`.** PDF 는 스펙이 방대해 직접 구현할 대상이 아니고, `pdf-lib` 은 순수 JS 라 서버가 필요 없다(NFR-02 유지).
- **번들 대책** `pdf-lib` 은 gzip 178KB 다. `lib/pdfTools.js` 의 `loadPdfLib()` 에서 **동적 `import()`** 로 불러오므로, `/pdf` 에 들어와 실제로 작업을 시작할 때만 내려받는다. 다른 45개 도구 사용자에게는 전송되지 않는다.
- **메타데이터 제거** 작성자·제작 프로그램·생성 일시가 PDF 에 남는다. 이력서를 뿌리기 전에 지우라고 만든 기능이다.

## 6. 계산 · 변환 (5종)

### `/timestamp` — 타임스탬프 변환
- **무엇** Unix 초/밀리초 ↔ 날짜, ISO·RFC 표기, 상대 시간.
- **어떻게** **KST(+09:00) 를 1급 시민으로 다룬다.** 브라우저 로컬 타임존에 의존하면 해외에서 열었을 때 결과가 달라지고 테스트도 재현되지 않는다. 그래서 KST 계산은 고정 오프셋으로 직접 한다.

### `/cron` — cron 표현식 해석기
- **무엇** cron 식을 한국어 문장으로 풀고 다음 실행 시각을 보여준다.
- **어떻게** 5필드(분·시·일·월·요일)와 **6필드**(초 포함 — Spring `@Scheduled` 스타일)를 모두 지원한다. 다음 실행 시각은 KST 고정으로 계산한다.

### `/number-base` — 진법 변환 · 비트 연산
- **무엇** 2/8/10/16진 상호 변환, AND·OR·XOR·시프트, 비트 시각화.
- **어떻게** 내부 표현을 **BigInt 로 통일**했다. 64비트 값을 `Number` 로 다루면 정밀도가 깨진다. 8/16/32/64비트 폭과 부호 있는/없는 해석을 선택할 수 있다.
- **화면** 하는 일이 둘이라 **탭으로 가른다**(진법 변환 / 비트 연산). 한 화면에 세로로 쌓으면 아래 절반이 안 보인다. 비트폭은 "몇 칸짜리 그릇인가" 라 두 탭이 함께 쓴다.

### `/bytes` — 바이트 크기 변환
- **무엇** B ↔ KB/MB/GB ↔ KiB/MiB/GiB.
- **어떻게** **1000 단위와 1024 단위를 나란히 보여준다.** 디스크 용량·전송량 계산에서 자주 헷갈리는 지점이다.
- **표기** 정식 이름(`KB` / `KiB`)을 그대로 쓴다. 윈도우 탐색기가 1024 를 세면서 "KB" 라고 적는 탓에 `KiB` 를 처음 보는 사람이 많지만, 감추면 실제 문서·설정에서 마주쳤을 때 못 알아본다. 대신 단위 셀렉트의 묶음 제목에 어디서 쓰는 값인지 적는다.
- **입력** 숫자 칸과 단위 셀렉트를 나눴다. 한 칸에 `1.5 GiB` 를 적게 하면 어떤 단위를 쓸 수 있는지 화면만 봐서는 알 수 없다.

### `/color` — 색상 변환 · 대비 검사
- **무엇** HEX ↔ RGB ↔ HSL ↔ HSV, WCAG 명암비 판정(AA/AAA).
- **어떻게** 색 이름표 내장. 명암비는 WCAG 상대 휘도 공식.
- **화면** 하는 일이 둘이라 **탭으로 가른다**(색상 변환 / 명암비 검사). 고른 색은 두 탭이 함께 써서, 변환하다 바로 대비를 볼 수 있다. 명암비 탭은 글자색·배경색을 나란히 받는다.
- **테스트 노트** HSL 왕복 변환은 **본질적으로 무손실이 아니다**(정수 반올림). 테스트를 ±2 허용으로 완화하고, 대신 RGB 왕복은 무손실임을 별도로 검증한다.

## 7. 웹 · 네트워크 (5종)

### `/url` — URL 인코더 · 쿼리 파서
- **무엇** percent 인코딩/디코딩 + URL 을 스킴·호스트·경로·쿼리 파라미터 표로 분해.
- **어떻게** 전체 이스케이프(component)와 URL 구조 보존(full) 을 구분해 제공한다. 리다이렉트·OAuth 콜백 URL 을 뜯어볼 때 쓴다.

### `/cidr` — IP · 서브넷 계산기
- **무엇** CIDR 로 네트워크·브로드캐스트·호스트 범위·넷마스크 계산, 서브넷 분할, 포함 여부 확인.
- **어떻게** IPv4 를 32비트 정수로 다룬다. 사설 대역 여부도 표시한다. 분할 결과는 256개로 상한(브라우저 보호).

### `/qr` — QR 코드 생성기
- **무엇** URL·텍스트를 QR 로 만들어 SVG·PNG 로 저장.
- **어떻게** **ISO/IEC 18004 를 직접 구현했다**(외부 라이브러리 없음). 바이트 모드(UTF-8), 오류정정 L/M/Q/H, 버전 1~6(최대 136바이트). Reed–Solomon 오류정정 코드워드 생성, 마스크 패턴 8종 평가, 파인더·타이밍·정렬 패턴 배치까지 포함한다.
- **스캐너 없이 검증한 방법** 생성된 QR 이 맞는지 눈으로는 못 본다. 그래서 **Reed–Solomon 신드롬이 0 인지** 검사했다(오류가 없으면 신드롬은 반드시 0). 여기에 구조 검증(파인더 3개 위치·타이밍 패턴 교대·다크 모듈)을 더해 자동 테스트로 고정했다.
- **버전 7 이상을 뺀 이유** 버전 정보 블록(18비트)이 추가로 필요하다. 로컬 개발 서버 주소·URL 공유라는 실사용 목적에는 버전 6 으로 충분하다.

### `/curl` — cURL → 코드 변환
- **무엇** 브라우저 개발자도구에서 "Copy as cURL" 한 걸 fetch·axios·Java HttpClient·Python requests 코드로 바꾼다.
- **어떻게** 셸 토크나이저를 먼저 만들었다(따옴표·이스케이프·줄바꿈 연속(`\`) 처리). 그 다음 옵션(`-X -H -d --data-raw -u --compressed …`)을 파싱해 중간 표현으로 만들고, 언어별 생성기가 그걸 찍어낸다.

### `/utm` — UTM 링크 만들기
- **무엇** 캠페인 추적 파라미터를 붙인 링크를 만들고, 반대로 붙어 있는 UTM 을 분해한다.
- **어떻게** `URL`·`URLSearchParams` 로 조립. 필드별 관행값 프리셋 제공.
- **개발 중 잡은 버그** 분해 기능에서 `searchParams.forEach` 로 순회하면서 동시에 `delete` 하면 **항목을 건너뛴다**(`utm_medium` 이 남는 현상). 키를 먼저 모아둔 뒤 지우도록 고쳤다.

## 7-1. 다이어그램 (6종)

> 구조·mermaid 도입 결정·파서 한계는 **`05_다이어그램.md`** 가 자세히 다룬다. 여기서는 목록만.

여섯이 `components/DiagramTool.jsx` 하나를 나눠 쓴다. 경로를 따로 둔 건 검색어가 서로 다르기 때문이다
("ERD 그리기" ≠ "시퀀스 다이어그램").

| 경로 | 무엇 | 코드 붙여넣기 |
|---|---|---|
| `/erd` | 테이블 관계도 | ✅ `CREATE TABLE` 을 읽어 FK 관계선까지 잇는다 |
| `/class-diagram` | UML 클래스 다이어그램 | ✅ 자바 소스의 `extends`·`implements`·JPA 연관을 읽는다 |
| `/sequence` | 시퀀스 다이어그램 | — (한국어 예시 제공) |
| `/flowchart` | 순서도 | — |
| `/state-diagram` | 상태 다이어그램 | — |
| `/diagram` | 간트·마인드맵·여정·깃그래프·C4 등 20여 종 | — |

- **이 도구가 더하는 값은 앞의 둘이다.** mermaid 문법을 배워야 쓰는 편집기는 이미 여럿이라
  거기 하나를 더 얹는 건 의미가 없다. **이미 갖고 있는 코드를 붙여넣으면 그림이 나오는 것**이 우리 몫이다.
- **렌더링은 mermaid.** 레이아웃 엔진을 직접 쓰면 더 못한 그림이 나오고 종류마다 새로 만들어야 한다.
  우리가 잘할 수 있는 건 파싱이지 배치가 아니다.
- **번들**: gzip 950KB 지만 `lib/mermaidRender.js` 밖에서 절대 import 하지 않고, mermaid 가 종류별로
  35개 청크로 갈라져 **쓰는 종류만** 내려온다. 다이어그램을 안 쓰는 사용자의 첫 진입은 도입 전과 같다.
- **테스트가 세 겹**인 이유는 `05` 문서에 적었다 — 문자열 단언은 통과하는데 mermaid 가 거부하는 경우가
  실제로 넷 있었다.

## 9. NFR-02 실측

"브라우저 안에서만 동작한다" 는 주장을 코드로 확인한 결과다.

| 검사 | 결과 |
|---|---|
| `fetch(` · `XMLHttpRequest` · `axios` · `sendBeacon` · `new WebSocket` 호출 | **0건** — 검색에 걸리는 것은 전부 `/curl` **코드 생성기가 만들어 내는 문자열**이다 |
| 서버 API | 0개 (백엔드에 받을 엔드포인트가 없다) |
| localStorage 에 저장되는 것 | `dtb.settings` · `dtb.schema_version` · `dtb.canvas.*`(그리기 탭에서 그린 도형·좌표 — 이어서 편집하려고 남긴다). 도구 입력 원문은 0건 |
| 파일(이미지·PDF) | 메모리에서만 처리 후 폐기. 업로드·저장 경로 없음 |

**예외 0건.** `/og-preview` 를 걷어내면서 바깥으로 나가던 마지막 요청(입력한 `og:image` 로드)이 사라졌다.
아이콘 폰트도 `public/fonts/` 에서 직접 서빙한다. 그래서 CSP 의 `img-src` 에서도 외부 출처를 뺐다.

`dangerouslySetInnerHTML` 은 앱 전체에 **1곳**(`/qr` 의 SVG 렌더)뿐이며,
그 SVG 문자열은 숫자 좌표와 고정 색상만으로 만들어져 **입력 텍스트가 들어갈 경로가 없다**(검수 확인).

## 10. 백엔드가 하는 일 (전부)

```
GET /healthz                 → 200 (Railway 헬스체크)
GET /actuator/health, /info  → 배포 진단
GET /  및 도구 41개 경로      → forward:/index.html  (SPA 새로고침·직접 접속 대응)
그 외 모든 요청              → denyAll (403)
```

- **서버 API 0개. DB 0개.** 백엔드 클래스는 5개, 의존성은 4개뿐이다(상세: `02_구조.md`).
- `SecurityConfig` 는 **화이트리스트 방식**이다 — 공개 경로를 명시하고 나머지는 `denyAll`. 새 도구를 추가하면서 여기 등록을 빠뜨리면 그 URL 만 403 이 난다. §1 의 테스트 두 개가 이걸 막는다.
- 클릭재킹 방어(`frameOptions sameOrigin`), 무상태(세션·폼로그인·CSRF 표면 없음).

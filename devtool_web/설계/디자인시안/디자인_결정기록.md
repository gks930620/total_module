# 디자인 시안 결정 기록

> 같은 방향을 두 번 시도하지 않기 위한 기록입니다. **새 시안을 만들기 전에 이 문서부터 읽으세요.**

---

## 1차 (2026-08-04) — 5개 제시, **4개 탈락 / 1개 통과**

넓게 벌려서 5가지 방향을 시험했습니다. 결과:

| 시안 | 방향 | 판정 |
|---|---|:--:|
| A. Blueprint | 다크 + 모노스페이스 + 고밀도, IDE 감성 | ❌ **탈락** |
| B. Paper | 크림 지면 + 명조 + 넓은 여백, 에디토리얼 | ❌ **탈락** |
| C. Brutalist | 3px 검정 테두리 + 하드 그림자 + 원색 | ❌ **탈락** |
| **D. Soft** | **파스텔 그라디언트 + 큰 라운드 + 떠 있는 카드** | ✅ **통과 — 유지** |
| E. Console | 아이콘 레일 3단 + 초고밀도 + 홈이 표 | ❌ **탈락** |

**사용자 코멘트(2026-08-05):** "ABCE 다 별로고 D 남기고 다른 시안 더 만들어봐."

### 탈락본은 어디에 있나

`보류/` 폴더에 그대로 남겨 뒀습니다. 언제든 다시 열어 볼 수 있습니다.

```
설계/디자인시안/보류/a-blueprint.html
설계/디자인시안/보류/b-paper.html
설계/디자인시안/보류/c-brutalist.html
설계/디자인시안/보류/e-console.html
```

폴더 안에 전용 `shared.js` 사본을 함께 넣어 뒀으므로 **그 자리에서 그대로 열립니다.**
보류본끼리 비교 바 이동도 되고, D 를 누르면 상위 폴더의 채택본으로 넘어갑니다.

### 이 결과에서 읽어낸 것 — **다시 만들지 말아야 할 방향**

4개가 한꺼번에 떨어졌고 살아남은 하나가 D 라는 사실에서 방향이 꽤 분명하게 드러납니다.

| 버려진 속성 | 어느 시안에서 | 판단 |
|---|---|---|
| **다크 기본** | A | 다시 시도하지 않음. (다크 *모드*는 별개 — 이미 구현돼 있고 유지) |
| **고밀도·촘촘한 행** | A, E | 정보를 빽빽이 채우는 방향은 취향이 아님 |
| **각진 모서리(0~4px)** | A, C, E | 라운드가 있어야 함 |
| **딱딱한 테두리 중심 구획** | A, C, E | 선으로 나누기보다 면·그림자로 나누는 쪽 |
| **세리프(명조) 제목** | B | 본문용 sans 계열이 맞음 |
| **원색·강한 대비** | C | 채도 높은 원색 블록은 부담스러움 |
| **복잡한 IA(3단 레일)** | E | 계층을 깊게 파는 구조는 과함 |
| **카드 없는 구성** | B | 카드로 묶어 주는 편이 나음 |

### 반대로 D 에서 통했다고 보는 것

- 밝은 배경 + 은은한 그라디언트
- **큰 라운드(18~24px)**
- 테두리 대신 **넓고 옅은 그림자**로 요소를 띄우는 방식
- 넉넉한 여백 (밀도보다 호흡)
- 파스텔 계열의 부드러운 색
- 그룹별 아이콘 배지 + 카드 그리드

## 2차 (2026-08-05) — D 유지 + 신규 4개

1차에서 방향이 좁혀졌으므로 **이번에는 멀리 벌리지 않습니다.**
"밝고 부드럽고 카드 기반"이라는 D 의 전제는 공유하되, 그 안에서 성격을 갈랐습니다.
탈락한 A·B·C·E 의 속성(다크·고밀도·각진·원색·세리프)은 **의도적으로 배제**했습니다.

> 알파벳을 A~E 로 다시 쓰지 않고 **F 부터 이어 붙입니다.** 나중에 이 기록을 읽을 때
> "A" 가 1차의 탈락본인지 2차의 신규본인지 헷갈리지 않게 하기 위함입니다.

| 시안 | 방향 | D 와의 차이 |
|---|---|---|
| **D. Soft** *(1차 통과, 유지)* | 파스텔 그라디언트 · 균일한 카드 | — 기준점 |
| **F. Aurora** | 글래스모피즘 · 반투명 블러 카드 · 비비드 그라디언트 | D 보다 **채도·대비를 올린** 버전. 배경이 비쳐 보임 |
| **G. Clean** | 절제된 미니멀 · 흰 배경 · 얇은 선 · 라운드 10px | D 보다 **차분하고 프로페셔널**. 장식 최소, 타이포 위계 중심 |
| **H. Warm** | 따뜻한 크림·살구·올리브 · 둥근 서체 · 큰 글씨 | D 가 **차가운** 파스텔(보라·하늘)이라면 H 는 **따뜻한** 파스텔 |
| **I. Bento** | 벤토 그리드 · 크기가 다른 타일 · 타일마다 다른 배경색 | D 와 색은 비슷하나 **레이아웃 리듬이 완전히 다름** |

### 2차 판정 (2026-08-05)

| 시안 | 판정 | 메모 |
|---|:--:|---|
| **D. Soft** | ✅ **통과** | "D는 더 깔끔하고" |
| **F. Aurora** | ✅ **통과** | "F는 조금 더 화려하고" |
| **G. Clean** | ✅ **통과(유지)** | "클린은 냅두자" |
| H. Warm | ❌ **탈락** | 보류/h-warm.html |
| I. Bento | ❌ **탈락** | 보류/i-bento.html |

**사용자 코멘트:** "d랑 f가 둘다 좋네. D는 더 깔끔하고, F는 조금더 화려하고..
사실 2개 비슷해보이는데 이거 합친거 하나만 더 추가해봐. HI는 없애고 클린은 냅두자."

### 2차에서 추가로 확정된 것

방향이 훨씬 좁아졌습니다.

| 확정된 것 | 근거 |
|---|---|
| **색온도는 차가운 쪽**(보라·하늘·핑크) | H(살구·모래·올리브) 탈락. 따뜻한 파스텔은 아니다 |
| **배치는 균일한 카드 그리드** | I(크기가 다른 벤토 타일) 탈락. 리듬을 주는 비균일 배치는 아니다 |
| **사이드바 유지** | I 만 사이드바가 없었고 탈락. 좌측 사이드바 구조가 맞다 |
| **파스텔~비비드 사이 어딘가** | D·F 가 둘 다 통과. 채도의 정답은 이 구간 안에 있다 |
| **절제된 미니멀도 후보로 살아 있음** | G 유지 — 다만 "좋다"가 아니라 "냅두자"였으므로 1순위는 아니다 |

### 짚어야 할 지적 — "D와 F가 비슷해 보인다"

맞는 지적이고, 원인이 있습니다. **D 와 F 는 둘 다 화면 '전체'의 톤을 정하는 방식**이었습니다.
D 는 전체가 차분하고 F 는 전체가 화려해서, 차이가 "톤이 조금 다르다" 로만 느껴진 겁니다.
같은 레이아웃·같은 컴포넌트에 채도만 다르게 입혔으니 당연한 결과입니다.

→ 3차의 J 는 이 지적에 대한 답입니다. 톤을 섞는 대신 **역할을 나눴습니다**(아래).

## 3차 (2026-08-05) — D·F·G 유지 + J(합본) 신규

| 시안 | 방향 |
|---|---|
| **D. Soft** ✅ | 파스텔 · 전체가 차분함 |
| **F. Aurora** ✅ | 비비드 · 전체가 화려함 |
| **G. Clean** ✅ | 미니멀 · 장식 최소 |
| **J. Halo** 🆕 | **D + F 합본 — "화려함을 한 곳에 모은다"** |

### J 의 설계 원칙

단순히 D 와 F 의 중간 채도를 쓰는 건 답이 아닙니다(그러면 셋이 더 비슷해집니다).
J 는 **화면의 부위마다 어느 쪽을 따를지를 나눴습니다**:

| 부위 | 어느 쪽을 따르나 | 이유 |
|---|---|---|
| 카드·패널·본문 (읽는 면) | **D** — 불투명 흰색, 차분하게 | F 의 반투명 카드는 예뻤지만 데이터를 읽는 면으로는 배경이 비쳐 산만하다 |
| 히어로·주 버튼·활성 항목·아이콘 배지·결과 배지 (보는·누르는 곳) | **F** — 그라디언트 | 전체의 10% 정도만 화려하면 나머지가 더 조용해 보인다 |
| 헤더 | **F** — 유리(blur) | 콘텐츠가 실제로 뒤로 지나가는 유일한 자리. 블러가 장식이 아니라 기능이 되는 곳 |
| 배경 | 절충 — F 의 메시를 쓰되 면적을 줄이고 위쪽에만 | 아래로 갈수록 차분해져 본문에 집중된다 |

여기에 **J 만의 디테일**로 카드 윗변의 1px 그라디언트 선을 넣었습니다.
평소엔 거의 안 보이다가 hover 하면 또렷해집니다 — "조용한데 살아 있는" 느낌을 만드는 장치입니다.

### 3차 판정 (2026-08-05) — **확정**

| 시안 | 판정 |
|---|:--:|
| D. Soft | ❌ 미채택 |
| F. Aurora | ❌ 미채택 |
| G. Clean | ❌ 미채택 |
| **J. Halo** | ✅ **채택 — 실제 코드에 적용 완료** |

**사용자 코멘트:** "J (헤일로)가 가장 맘에 드네 이걸로 하자. 프로젝트에 이거 적용해줘"

> 세 라운드, 시안 10개 만에 확정. **디자인 논의는 여기서 종료**합니다.
> D·F·G 목업은 참고용으로 이 폴더에 남겨 두지만, 이후 UI 변경의 기준은
> **`frontend/src/styles.css` 의 실제 토큰**입니다(목업이 아니라).

### 코드 적용 내역 (2026-08-05)

| 파일 | 무엇 |
|---|---|
| `frontend/src/styles.css` | 디자인 토큰 전면 교체(라이트+다크) + 레이아웃·컴포넌트 규칙. 머리말에 J 원칙 4개 명시 |
| `frontend/src/styles-tools.css` | 도구 공통 컴포넌트 20여 종을 J 규칙으로 재작성 |
| `frontend/src/components/ToolHeader.jsx` | 그라디언트 도구 아이콘 추가. 아이콘은 **경로로 `tools.js` 에서 조회**(22개 페이지 무수정) |
| `frontend/src/pages/HomePage.jsx` | `data-group` 속성 추가 — 그룹별 아이콘 배지 그라디언트를 CSS가 고르도록 |

**적용된 J 원칙 4개** (styles.css 머리말에도 주석으로 박아 뒀습니다):

1. **읽는 면은 불투명** — 카드·패널·사이드바·본문은 흰색 불투명. 유리·그라디언트 없음.
2. **초점에만 그라디언트** — 히어로 / 주 버튼 / 활성 사이드바 항목 / 도구 아이콘 / 로고 마크 /
   현재시각 바 / HTTP 코드 배지 / 선택된 칩 / 그룹 제목 앞 막대.
3. **유리(backdrop-blur)는 헤더에만** — 콘텐츠가 실제로 뒤로 지나가는 유일한 자리.
   `--glass` 토큰으로 고정(`color-mix` 미지원 브라우저 대비).
4. **카드 윗변 1px 그라디언트 선** — `::before` 로 평소 opacity .16, hover 시 .85.

부수 변경: 라운드 10px → **20px**, 버튼·칩·배지 전부 **알약형**,
테두리 대신 그림자로 구획, 사이드바가 화면 가장자리에서 떨어진 **떠 있는 카드**로,
kv 행의 복사 버튼은 **hover 시에만** 노출(평소 화면을 조용하게).
